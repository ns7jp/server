# 6. 通信のしくみと名前解決・リモート接続

[用語集の入口](README.md) / [さくいん](index.md) / [前: ネットワークの基礎](05-network-basics.md) / [次: Web とアプリケーション](07-web.md)

サーバーの現場でいちばん多い相談は「つながらないんですけど」です。この章では、その原因を切り分けるための言葉を、通信の入口・名前解決・リモート接続の順に並べます。

> **この章で最初に押さえる 3 語**: ポート番号 ／ 名前解決 ／ SSH

<a id="g-net2-tcp-udp"></a>
## TCP と UDP（ティー・シー・ピー と ユー・ディー・ピー）

- **一言**: 届いたか確認しながら送るのが TCP、確認せず送りっぱなしが UDP です。
- **たとえ**: TCP は配達記録つきの宅配便で、受け取りのサインがなければ何度でも送り直します。UDP は広場のアナウンスで、聞こえたかどうかは確かめません。
- **くわしく**: どちらもデータを運ぶための決まりごと（プロトコル）で、IP（住所をもとに届ける仕組み）の上で動きます。TCP は順番の入れ替わりや消えたデータを直してから渡すので、Web やメール、SSH などに使われます。UDP は確認をしない分だけ速くて軽いので、DNS の問い合わせや音声・動画の配信に向きます。
- **覚え方**: T は「丁寧に確認」、U は「打ちっぱなし」と対にして覚えます。
- **まちがえやすい**: UDP は壊れた通信ではなく、速さを優先して確認を省いた設計です。同じ 53 番でも TCP と UDP は別枠なので、片方しか開いていなくて通らないことがあります。
- **関連語**: [3 ウェイハンドシェイク](#g-net2-three-way-handshake) / [コネクション](#g-net2-connection) / [ポート番号](#g-net2-port-number)
- **確かめかた**: `ss -tuln` で TCP（t）と UDP（u）の待ち受けを並べて見られます（`ss` が無い環境では `netstat -tuln` を使います）。

<a id="g-net2-three-way-handshake"></a>
## 3 ウェイハンドシェイク（スリー・ウェイ・ハンドシェイク）

- **一言**: TCP が通信を始める前に、3 回のやり取りで合図を交わす手順です。
- **たとえ**: 電話で「もしもし」「はい、聞こえます」「では話しますね」と 3 回言ってから本題に入るのと同じです。
- **くわしく**: つなぐ側が SYN（つなぎたい）を送り、サーバーが SYN/ACK（いいですよ）を返し、つなぐ側が ACK（了解）を返して成立します。この 3 回が終わって、はじめてデータが流れ始めます。`SYN-SENT` のまま止まるときは、経路の途中のファイアウォール（通信を選別する仕組み）で捨てられていることがよくあります。
- **覚え方**: 「呼ぶ・応える・確かめる」の 3 拍子で、SYN → SYN/ACK → ACK と唱えます。
- **まちがえやすい**: ping が通ることと、目的のポートで 3 ウェイハンドシェイクが成立することは別です。ping は ICMP という別の仕組みなので、ポートが閉じていても応答が返ることがあります。
- **関連語**: [TCP と UDP](#g-net2-tcp-udp) / [コネクション](#g-net2-connection) / [ICMP と ping](#g-net2-icmp-ping)
- **確かめかた**: `ss -tan` を実行し、`SYN-SENT` のまま止まっている接続がないかを見ます。

<a id="g-net2-connection"></a>
## コネクション

- **一言**: 2 台の間に開かれた、データが行き来する 1 本の通り道です。
- **たとえ**: 電話がつながっている状態そのものです。切るまでは同じ相手と話し続けられます。
- **くわしく**: TCP のコネクションは「送信元 IP アドレス・送信元ポート・宛先 IP アドレス・宛先ポート」の 4 つの組で区別されます。だから同じサーバーの 443 番に何人がつないでも、通信が混ざることはありません。閉じたあとも `TIME-WAIT` としてしばらく残り、すぐには消えません。
- **覚え方**: 自分側と相手側、両方の「住所と部屋番号」がそろって 1 本と数えます。
- **まちがえやすい**: 「つながった」と「サービスが正常」は別です。コネクションが張れていても、アプリがエラーを返し続けていることはよくあります。
- **関連語**: [TCP と UDP](#g-net2-tcp-udp) / [ソケット](#g-net2-socket) / [3 ウェイハンドシェイク](#g-net2-three-way-handshake)
- **確かめかた**: `ss -tn state established` で、いま実際につながっている相手を一覧できます。

<a id="g-net2-port-number"></a>
## ポート番号（ポートバンゴウ）

- **一言**: 1 台のサーバーの中で、どのサービス宛ての通信かを示す番号です。
- **たとえ**: IP アドレスがマンションの住所なら、ポート番号は部屋番号です。同じ建物でも部屋が違えば、別の住人に届きます。
- **くわしく**: 0 から 65535 までの番号があり、サーバー側は決めた番号で待ち受けます。つなぐ側の番号は、空いているものが自動で割り当てられます。「サーバーは動いているのにつながらない」ときは、まずどの番号で待ち受けているかを確かめます。
- **覚え方**: 住所（IP アドレス）＋部屋番号（ポート番号）で、届け先が 1 つに決まります。
- **まちがえやすい**: 番号を変えても、それだけで安全になるわけではありません。機械的な総当たりは減りますが、認証の強さとは別の話です。
- **関連語**: [ウェルノウンポート](#g-net2-well-known-port) / [listen と bind](#g-net2-listen-bind) / [ソケット](#g-net2-socket)
- **確かめかた**: `ss -ltn` で、待ち受け中のポート番号を一覧できます。

<a id="g-net2-well-known-port"></a>
## ウェルノウンポート：22・53・80・443 など

- **一言**: よく使うサービス用に、あらかじめ決められている番号のことです。
- **たとえ**: 110 番は警察、119 番は消防と決まっているのと同じで、番号を見ればサービスの見当がつきます。
- **くわしく**: 0 番から 1023 番までがこの範囲で、代表例は SSH が 22 番、DNS が 53 番、HTTP が 80 番、HTTPS が 443 番です。ほかに FTP が 21 番、SMTP が 25 番などがあります。Linux ではこの範囲で待ち受けるのに管理者権限が必要になるのが一般的ですが、扱いは環境によって異なります。
- **覚え方**: 「入口 22、名前 53、Web は 80 と 443」と口に出して覚えます。
- **まちがえやすい**: 決まりごとであって強制ではありません。80 番で SSH を動かすこともできるので、番号だけでサービスを断定はできません。
- **関連語**: [ポート番号](#g-net2-port-number) / [DNS](#g-net2-dns) / [SSH](#g-net2-ssh)
- **確かめかた**: `getent services ssh` や `getent services https` で、番号とサービス名の対応を確認できます。

<a id="g-net2-listen-bind"></a>
## listen と bind（リッスン と バインド）

- **一言**: bind は使う窓口を確保すること、listen はそこで客待ちを始めることです。
- **たとえ**: お店で「この住所のこの窓口を借ります」と場所を押さえるのが bind、「開店したので並んでください」と受け付け始めるのが listen です。
- **くわしく**: プログラムはまず IP アドレスとポート番号の組を bind で押さえ、そのあと listen で接続待ちに入ります。同じ組み合わせは原則として 1 つのプログラムしか押さえられず、二重に起動すると「アドレスは既に使用中」で失敗します。`0.0.0.0` に bind すればその機械が持つすべての IPv4 アドレスで受け付け、`127.0.0.1` だけなら同じ機械の中からしか届きません。
- **覚え方**: bind は場所取り、listen は呼び込み開始で、場所を取ってから呼び込みます。
- **まちがえやすい**: 「起動しているのに外からつながらない」原因の多くは、`127.0.0.1` にだけ bind していることです。この場合はファイアウォールを開けても直りません。
- **関連語**: [ポート番号](#g-net2-port-number) / [ソケット](#g-net2-socket) / [コネクション](#g-net2-connection)
- **確かめかた**: `ss -ltnp` で、どのアドレスに bind して listen しているかを確認します（プログラム名の表示には管理者権限が要ることがあります）。

<a id="g-net2-socket"></a>
## ソケット

- **一言**: プログラムが通信するときにつかむ、データの出入口のことです。
- **たとえ**: 壁のコンセントの差し込み口です。器具（アプリ）を差し込んで、電気（データ）をやり取りします。
- **くわしく**: OS が用意する通信の入口で、プログラムはファイルを読み書きするのに近い感覚でデータを送受信します。ネットワーク越しの TCP や UDP のソケットのほかに、同じ機械の中だけで使う UNIX ドメインソケット（ファイルとして置かれる通信口）もあります。データベースへの接続設定などで、どちらを使うかを選ぶ場面が出てきます。
- **覚え方**: 電源のソケットと同じ言葉で、「差し込んではじめて通じる穴」と覚えます。
- **まちがえやすい**: ソケットとポートは別物です。ポートは番号そのもので、ソケットはその番号を使って実際に開かれた通信口です。
- **関連語**: [ポート番号](#g-net2-port-number) / [listen と bind](#g-net2-listen-bind) / [コネクション](#g-net2-connection)
- **確かめかた**: `ss -x` で、UNIX ドメインソケットの一覧を確認できます。

<a id="g-net2-icmp-ping"></a>
## ICMP と ping（アイ・シー・エム・ピー と ピング）

- **一言**: ICMP は通信の連絡用の決まりごと、ping はそれで生存を確かめる道具です。
- **たとえ**: 相手の家の前で「いますかー」と声をかけて、返事があるかどうかだけを見る確認です。
- **くわしく**: ICMP は「届きませんでした」などの通知に使われる、制御専用の決まりごとです。ping は ICMP のエコー要求を送り、応答が返るまでの時間を表示します。返らないときは、相手が止まっているのか、途中で ICMP を止められているのか、そもそも名前解決に失敗しているのかを切り分けます。
- **覚え方**: ping は潜水艦のソナー音で、跳ね返りだけで相手の存在を確かめます。
- **まちがえやすい**: ping が通らない＝サーバーが落ちている、ではありません。ICMP だけ止める環境は珍しくなく、逆に ping が通ってもサービスが動いているとは限りません。
- **関連語**: [traceroute](#g-net2-traceroute) / [TCP と UDP](#g-net2-tcp-udp) / [名前解決](#g-net2-name-resolution)
- **確かめかた**: `ping -c 4 example.com` のように回数を指定して実行します（Windows では `ping -n 4 example.com` です）。

<a id="g-net2-traceroute"></a>
## traceroute・tracert（トレースルート／トレーサート）

- **一言**: 相手に届くまでに通った中継地点を、順番に洗い出す道具です。
- **たとえ**: 宅配便の追跡履歴です。どの営業所まで進んだか、どこで止まっているかが並んで見えます。
- **くわしく**: パケットの寿命（TTL、あと何台の機器を通れるかの回数）を 1 ずつ増やしながら送り、途中の機器から返る応答を並べて経路を表示します。Windows では `tracert`、Linux では `traceroute` や `tracepath` を使います。道具によって送る中身が UDP だったり ICMP だったりするので、同じ相手でも結果が違って見えることがあります。
- **覚え方**: trace（追跡）＋route（経路）で、「どこまで行けたかの追跡番号」と覚えます。
- **まちがえやすい**: 途中に `*` が並んでも異常とは限らず、応答を返さない設定の機器を通っただけのこともあります。ここでの TTL はパケットの残り回数で、DNS の TTL（キャッシュを持つ秒数）とは別物です。
- **関連語**: [ICMP と ping](#g-net2-icmp-ping) / [コネクション](#g-net2-connection) / ルーティング
- **確かめかた**: `traceroute example.com`（Windows は `tracert example.com`）で経路を表示します。未導入の環境では `tracepath example.com` でも近いことができます。

<a id="g-net2-dns"></a>
## DNS（ディー・エヌ・エス）

- **一言**: 名前と IP アドレスの対応を、世界中で分担して管理する仕組みです。
- **たとえ**: 電話帳です。相手の名前を引けば番号が分かるので、番号を暗記しなくても電話をかけられます。
- **くわしく**: 人が覚えやすい名前を、機械が使う IP アドレスに変換するための分散型のデータベースです。ルート、`.com` などの上位、各ドメインの担当サーバーへと順にたどって答えに行き着きます。障害調査では「まず名前が引けているか」を確かめるのが定番です。
- **覚え方**: Domain Name System の頭文字で、「ネットの電話帳」と覚えます。
- **まちがえやすい**: DNS は名前を教えるだけで、通信そのものは運びません。名前が引けても、そのサーバーにつながるかどうかは別の問題です。
- **関連語**: [名前解決](#g-net2-name-resolution) / [権威 DNS サーバーとキャッシュ DNS サーバー](#g-net2-authoritative-cache-dns) / [A レコード・AAAA・CNAME・MX・TXT](#g-net2-dns-record-types)
- **確かめかた**: `dig example.com` で問い合わせの結果を確認します（`dig` が入っていない環境では `nslookup example.com` を使います）。

<a id="g-net2-name-resolution"></a>
## 名前解決（ナマエカイケツ）

- **一言**: 名前から IP アドレスを調べ、実際に接続できる形にすることです。
- **たとえ**: 「駅前のあの店」と言われて、地図アプリで住所を割り出すまでの作業です。
- **くわしく**: OS はまず hosts ファイルなどの手元の設定を見て、次に設定された DNS サーバーへ問い合わせます。参照する順番も問い合わせ先も、環境によって異なります。「つながらない」ときは、名前解決で失敗しているのか、その先の通信で失敗しているのかを最初に切り分けます。
- **覚え方**: DNS は電話帳そのもの、名前解決はその電話帳を「引く」動作、と分けて覚えます。
- **まちがえやすい**: `ping` が「名前が見つかりません」で終わるのは、サーバーの停止ではなく名前解決の失敗です。エラーの文面を読み分けると、次に調べる場所が変わります。
- **関連語**: [DNS](#g-net2-dns) / [hosts ファイル](#g-net2-hosts-file) / [正引きと逆引き](#g-net2-forward-reverse-lookup)
- **確かめかた**: `getent hosts example.com` で OS が実際に返す結果を、`cat /etc/nsswitch.conf` で参照順の設定を確認できます。

<a id="g-net2-dig-nslookup"></a>
## dig と nslookup（ディグ と エヌエス・ルックアップ）

- **一言**: 名前解決だけを取り出して確かめる、DNS 専用の問い合わせ道具です。
- **たとえ**: 電話をかける前に、電話帳の記載だけを声に出して読み上げてみる確認です。
- **くわしく**: どちらも DNS サーバーへ問い合わせ、返ってきた答えをそのまま画面に出します。`dig` は答えの種類（A や MX）や問い合わせ先のサーバーまで細かく指定でき、調査に向きます。`nslookup` は Windows にも標準で入っているので、`dig` が無い環境で役立ちます。「つながらない」ときは、まずこの道具で名前が引けているかを見ます。
- **覚え方**: dig は「掘る」、lookup は「調べる」で、どちらも名前を引くだけの道具です。
- **まちがえやすい**: この 2 つは DNS サーバーへ直接聞くため、hosts ファイル（手元に書いた対応表）を見ません。OS が実際に使う答えを知りたいときは `getent hosts` で確かめます。
- **関連語**: [名前解決](#g-net2-name-resolution) / [DNS](#g-net2-dns) / [hosts ファイル](#g-net2-hosts-file)
- **確かめかた**: `dig example.com +short` で答えだけを表示できます。`nslookup example.com` でも同じ内容を確認できます。

<a id="g-net2-dns-record-types"></a>
## A レコード・AAAA・CNAME・MX・TXT（エー・レコード／クアッド・エー／シーネーム／エム・エックス／ティー・エックス・ティー）

- **一言**: DNS に登録する情報の種類で、種類ごとに答えの中身が違います。
- **たとえ**: 電話帳の欄の違いです。自宅の番号、携帯の番号、旧姓からの案内、郵便の宛先、備考欄が、それぞれ別の行になっています。
- **くわしく**: A は名前を IPv4 アドレスに、AAAA は IPv6 アドレスに対応させます。CNAME は「この名前は別の名前の別名です」と示し、MX はメールの配送先サーバーを指します。TXT は自由な文字列で、送信ドメインの認証や所有権の確認によく使われます。
- **覚え方**: A は Address、AAAA はその 4 倍の長さの IPv6 用、C は Canonical（正式名）、M は Mail、T は Text です。
- **まちがえやすい**: CNAME は別名なので、同じ名前に他のレコードを並べられません。ドメインの一番上（`example.com` そのもの）には置けないため、事業者ごとの代わりの機能で回避することが多いです。
- **関連語**: [DNS](#g-net2-dns) / [ゾーンと TTL](#g-net2-zone-ttl) / [サブドメイン](#g-net2-subdomain)
- **確かめかた**: `dig example.com A`、`dig example.com MX`、`dig example.com TXT` のように種類を指定して引きます。

<a id="g-net2-authoritative-cache-dns"></a>
## 権威 DNS サーバーとキャッシュ DNS サーバー（ケンイ・ディー・エヌ・エス・サーバー と キャッシュ・ディー・エヌ・エス・サーバー）

- **一言**: 答えを持っている側が権威、代わりに探して覚える側がキャッシュです。
- **たとえ**: 権威は本人が書いた名簿、キャッシュは受付係のメモです。受付は本人に聞いた内容を、しばらく手元に控えておきます。
- **くわしく**: 権威 DNS サーバーは、自分が担当するドメインの正解を返します。キャッシュ DNS サーバーは利用者からの依頼を受け、ルートから順にたどって答えを持ち帰り、一定時間ためておきます。設定を変えた直後に反映されないのは、この控えが残っているためです。
- **覚え方**: 権威は原本、キャッシュは写しで、写しは少し古いことがあると覚えます。
- **まちがえやすい**: 権威側を正しく直しても、キャッシュの保持時間が切れるまで古い答えが返り続けます。「自分の PC では新しいのに、他の人には古い」は、たいていこれが原因です。
- **関連語**: [DNS](#g-net2-dns) / [ゾーンと TTL](#g-net2-zone-ttl) / [名前解決](#g-net2-name-resolution)
- **確かめかた**: `dig +trace example.com` でルートからたどる様子を、`dig @192.0.2.53 example.com` の形で特定のサーバーの答えを確認できます（宛先の IP アドレスは環境に合わせます）。

<a id="g-net2-zone-ttl"></a>
## ゾーンと TTL（ゾーン と ティー・ティー・エル）

- **一言**: ゾーンは管理を任された名前の範囲、TTL はその答えの賞味期限です。
- **たとえ**: ゾーンは町内会の担当区域、TTL は掲示板の貼り紙に書かれた「◯日まで有効」の期限です。
- **くわしく**: ゾーンは権威 DNS サーバーが責任を持つ名前のかたまりで、その内容を書いた設定がゾーンファイルです。TTL は秒数で指定し、キャッシュ側はその時間だけ答えを持ち続けます。サーバーの引っ越し前に TTL を短くしておくと、切り替えが早く行き渡ります。
- **覚え方**: TTL は Time To Live（あと何秒生きられるか）の略で、ゾーンは「担当エリア」と覚えます。
- **まちがえやすい**: TTL を短くした設定自体も、行き渡るまでに元の TTL 分の時間がかかります。切り替えの直前に短くしても、間に合わないことがあります。
- **関連語**: [権威 DNS サーバーとキャッシュ DNS サーバー](#g-net2-authoritative-cache-dns) / [A レコード・AAAA・CNAME・MX・TXT](#g-net2-dns-record-types) / [DNS](#g-net2-dns)
- **確かめかた**: `dig example.com` の答えの行に出る数字が TTL（秒）です。キャッシュ経由なら残り時間、権威サーバーに直接聞けば設定した値そのものになります。

<a id="g-net2-hosts-file"></a>
## hosts ファイル（ホスツファイル）

- **一言**: DNS を使わず、名前と IP アドレスを手元で対応づける設定ファイルです。
- **たとえ**: スマホの連絡先に自分で書いたメモです。街の電話帳（DNS）より、自分のメモが先に見られます。
- **くわしく**: Linux では `/etc/hosts`、Windows では `C:\Windows\System32\drivers\etc\hosts` に置かれます。多くの環境で DNS より先に参照されるため、公開前のサーバーへ本番と同じ名前でつないで確認する、といった使い方ができます。参照される順番は設定によって異なります。
- **覚え方**: 「自分だけの電話帳」で、書いた 1 台にしか効かないと覚えます。
- **まちがえやすい**: 動作確認のために書いた行を消し忘れ、後日「自分の PC だけ古いサーバーにつながる」という事故が起きがちです。
- **関連語**: [名前解決](#g-net2-name-resolution) / [DNS](#g-net2-dns) / [ドメイン名と FQDN](#g-net2-domain-fqdn)
- **確かめかた**: `cat /etc/hosts` で中身を確認します（書き換えるのは、影響する範囲を確かめてからにします）。

<a id="g-net2-domain-fqdn"></a>
## ドメイン名と FQDN（ドメインメイ と エフ・キュー・ディー・エヌ）

- **一言**: ドメイン名は名前の範囲、FQDN は末尾まで省略しない完全な名前です。
- **たとえ**: `example.com` が「山田家」なら、`www.example.com` は「山田家の太郎さん宛て」まで書いた宛名です。
- **くわしく**: FQDN は Fully Qualified Domain Name の略で、`www.example.com` のようにホスト名からトップレベルドメインまで並べた形を指します。設定ファイルには原則として FQDN を書きます。短い名前だけを書くと、環境ごとの補完の設定に左右されて、別の相手につながることがあります。
- **覚え方**: FQDN の F はフルの F で、省略せず最後まで書く名前だと覚えます。
- **まちがえやすい**: `example.com` と `www.example.com` は別の名前です。片方だけ登録されていて、もう片方は引けないことがよくあります。
- **関連語**: [サブドメイン](#g-net2-subdomain) / [DNS](#g-net2-dns) / [名前解決](#g-net2-name-resolution)
- **確かめかた**: `hostname -f` で自分の FQDN を、`dig www.example.com` で相手の名前を確認します。

<a id="g-net2-subdomain"></a>
## サブドメイン

- **一言**: 持っているドメインの下に、点で区切って作る下位の名前です。
- **たとえ**: 会社の代表番号に対する内線番号です。`example.com` の下に `blog` や `mail` を並べて使い分けます。
- **くわしく**: `blog.example.com` のように、左側に名前を足して増やします。ドメインを買い足さなくても、自分の権威 DNS サーバーの設定だけで作れます。用途ごとにサーバーを分ける、本番と検証を分ける、といった使い分けに向きます。
- **覚え方**: 名前は右が上位、左が下位で、左に足すほど枝分かれします。
- **まちがえやすい**: サブドメインは、レコードを登録してはじめて引けます。ドメインを持っているだけで、自動的に使えるようになるわけではありません。
- **関連語**: [ドメイン名と FQDN](#g-net2-domain-fqdn) / [A レコード・AAAA・CNAME・MX・TXT](#g-net2-dns-record-types) / [ゾーンと TTL](#g-net2-zone-ttl)
- **確かめかた**: `dig blog.example.com` のように、作った名前を実際に引いて確認します。

<a id="g-net2-dns-round-robin"></a>
## DNS ラウンドロビン（ディー・エヌ・エス・ラウンドロビン）

- **一言**: 1 つの名前に複数の IP アドレスを登録し、順番に案内する方法です。
- **たとえ**: 同じ店名で入口を 3 つ用意し、来た人を順番に別の入口へ通す整理のしかたです。
- **くわしく**: 権威 DNS サーバーに A レコードを複数並べておくと、多くの DNS サーバーは問い合わせのたびに並び順を入れ替えて返します。特別な機器を足さずに負荷を分けられる、手軽な方法です。ただし振り分けは偏りやすく、細かい制御はできません。
- **覚え方**: round robin は「順番に回す」で、名前は 1 つ、行き先は複数と覚えます。
- **まちがえやすい**: 故障を見張る仕組みはありません。1 台落ちてもその IP アドレスは返り続けるので、一部の利用者だけつながらなくなります。
- **関連語**: [A レコード・AAAA・CNAME・MX・TXT](#g-net2-dns-record-types) / [ゾーンと TTL](#g-net2-zone-ttl) / [DNS](#g-net2-dns)
- **確かめかた**: `dig example.com A +short` を何度か実行し、並び順が変わるかを見ます（キャッシュの影響で変わらないこともあります）。

<a id="g-net2-forward-reverse-lookup"></a>
## 正引きと逆引き（セイビキ と ギャクビキ）

- **一言**: 名前から IP アドレスを調べるのが正引き、その逆をたどるのが逆引きです。
- **たとえ**: 電話帳で名前から番号を探すのが正引き、着信番号から相手の名前を割り出すのが逆引きです。
- **くわしく**: 正引きは A や AAAA レコードを、逆引きは PTR レコードを使います。逆引きは IP アドレスを配っている側（回線事業者やクラウド事業者）が設定するため、正引きは済んでいても逆引きは未設定、ということが起こります。メールの配送では、逆引きが未設定だと受け取りを断られることがあります。
- **覚え方**: 正は「名前 → 番号」、逆は「番号 → 名前」で、逆は別の担当者が設定すると覚えます。
- **まちがえやすい**: 正引きと逆引きは自動では一致しません。片方を直しても、もう片方は別に直す必要があります。
- **関連語**: [DNS](#g-net2-dns) / [名前解決](#g-net2-name-resolution) / [A レコード・AAAA・CNAME・MX・TXT](#g-net2-dns-record-types)
- **確かめかた**: `dig -x 192.0.2.1` で逆引きを確認します（`192.0.2.0/24` は説明用に予約された例示アドレスです）。

<a id="g-net2-smtp-pop3-imap"></a>
## SMTP・POP3・IMAP：メールサーバー（エス・エム・ティー・ピー／ポップ・スリー／アイマップ）

- **一言**: メールを送るのが SMTP、受け取って読むのが POP3 と IMAP です。
- **たとえ**: SMTP は郵便配達、POP3 は郵便受けの中身を家に持ち帰る受け取り方、IMAP は郵便受けを開けたまま中を眺める受け取り方です。
- **くわしく**: SMTP はメールを相手のメールサーバーまで届けるための決まりごとで、25 番などのポートを使います。POP3 は届いたメールを手元の端末に取り込む方式、IMAP はサーバーに置いたまま読む方式です。複数の端末で同じ受信箱を見る使い方が増えたため、いまは IMAP が主流です。どの方式でも、宛先のメールサーバーは MX レコードを引いて決まります。
- **覚え方**: S は Send（送る）で送信、P と I は受け取り側、と役割で分けて覚えます。
- **まちがえやすい**: 送信と受信は別の仕組みなので、片方だけ動かないことがあります。「メールが使えない」ときは、送る側と受け取る側のどちらで止まっているかを分けて調べます。
- **関連語**: [A レコード・AAAA・CNAME・MX・TXT](#g-net2-dns-record-types) / [ウェルノウンポート](#g-net2-well-known-port) / [正引きと逆引き](#g-net2-forward-reverse-lookup)
- **確かめかた**: `dig example.com MX +short` で配送先のサーバーを確認します。`getent services smtp` で番号とサービス名の対応も見られます。

<a id="g-net2-ntp"></a>
## NTP と時刻同期（エヌ・ティー・ピー と ジコクドウキ）

- **一言**: サーバーの時計を、正しい時刻へ自動で合わせ続ける仕組みです。
- **たとえ**: 電波時計です。放っておくとずれる時計を、基準の時報に合わせ続けてくれます。
- **くわしく**: NTP は Network Time Protocol の略で、上位の時刻サーバーと UDP の 123 番でやり取りしながら少しずつ時計を補正します。時刻がずれるとログの前後関係が読めなくなり、証明書の期限の判定や認証にも失敗します。Linux では `chronyd` や `systemd-timesyncd` が担当することが多いですが、使われるソフトは環境によって異なります。
- **覚え方**: NTP は「ネットの時報」で、ログを突き合わせる前にまず時計を疑います。
- **まちがえやすい**: 表示がおかしいとき、タイムゾーンの設定違いと時計そのもののずれは別の問題です。時差の分だけずれているのか、同期に失敗しているのかを見分けます。
- **関連語**: [TCP と UDP](#g-net2-tcp-udp) / ログ / TLS 証明書
- **確かめかた**: `timedatectl` で同期の状態を、`chronyc sources` で参照先を確認します（どちらが使えるかは環境によって異なります）。

<a id="g-net2-timezone-utc-jst"></a>
## タイムゾーンと UTC・JST（タイムゾーン と ユー・ティー・シー／ジェイ・エス・ティー）

- **一言**: 地域ごとの時刻の基準で、UTC は世界の基準、JST は日本の時刻です。
- **たとえ**: 空港に並ぶ世界時計です。同じ瞬間でも、ロンドンと東京の針は 9 時間ずれて見えます。
- **くわしく**: UTC は世界で共通に使う基準の時刻で、JST はそれより 9 時間進んだ日本の時刻です。サーバーやログの時刻を UTC のまま残す運用は多く、画面の表示が手元の感覚と 9 時間ずれて見えることがあります。ずれ幅がちょうど 9 時間なら、時計の故障ではなく表示の基準が違うだけです。Linux では `/etc/localtime` の設定で、どの地域の基準で表示するかが決まります。
- **覚え方**: 「JST は UTC より 9 時間進んでいる」と、日本が先だと覚えます。
- **まちがえやすい**: 時計を合わせる NTP とは別の話です。NTP が正常でも、タイムゾーンの設定が違えば表示は 9 時間ずれます。障害の時系列を並べるときは、どの基準で書かれた時刻かを先に確かめます。
- **関連語**: [NTP と時刻同期](#g-net2-ntp) / ログ / cron
- **確かめかた**: `timedatectl` でいま設定されている地域と時刻を確認します。`date` と `date -u` を見比べれば、UTC との差が分かります。

<a id="g-net2-ssh"></a>
## SSH（エス・エス・エイチ）

- **一言**: 離れたサーバーへ暗号化してログインし、操作するための仕組みです。
- **たとえ**: 自宅から会社のパソコンを、盗み聞きされない専用の通路ごしに操作する感覚です。
- **くわしく**: Secure Shell の略で、通信の中身が暗号化されるのが最大の特徴です。既定では 22 番ポートを使い、サーバー側では `sshd` というデーモン（ずっと待機し続けるプログラム）が待ち受けます。ログインだけでなく、ファイル転送や他の通信の中継にも使えます。
- **覚え方**: Secure（安全な）Shell（操作の窓口）で「安全な入口」と覚えます。
- **まちがえやすい**: 「SSH でつながらない」の原因は、名前解決・22 番への到達・認証の 3 つに分かれます。どこで止まっているかを分けて調べると早く進みます。
- **関連語**: [SSH の公開鍵認証](#g-net2-ssh-public-key-auth) / [踏み台サーバー](#g-net2-bastion) / [Telnet と FTP](#g-net2-telnet-ftp)
- **確かめかた**: `ssh -v user@example.com` の詳細表示で、どの段階まで進んだかを追えます。

<a id="g-net2-ssh-public-key-auth"></a>
## SSH の公開鍵認証（エス・エス・エイチ の コウカイカギニンショウ）

- **一言**: パスワードの代わりに、対になった鍵で本人確認をする方式です。
- **たとえ**: 玄関の鍵穴（公開鍵）をサーバーに預けておき、手元の鍵（秘密鍵）で開ける仕組みです。
- **くわしく**: サーバーの `~/.ssh/authorized_keys` に利用者の公開鍵を登録し、接続時に対応する秘密鍵を持っていることを証明します。秘密鍵そのものは通信路に流れません。パスワードのように盗み見や総当たりで破られにくいため、業務では標準的に使われます。
- **覚え方**: 「預けるのは鍵穴、持ち歩くのは鍵」で、逆にすると危険だと覚えます。
- **まちがえやすい**: 鍵ファイルやディレクトリの権限が緩いと、鍵が正しくてもログインを断られます。`~/.ssh` は 700、秘密鍵のファイルは 600 が基本です。
- **関連語**: [鍵ペア](#g-net2-key-pair) / [SSH](#g-net2-ssh) / [known_hosts とホスト鍵](#g-net2-known-hosts)
- **確かめかた**: `ssh -v user@example.com` の出力にある `Offering public key` の行で、どの鍵が試されたかを確認します。

<a id="g-net2-key-pair"></a>
## 鍵ペア：秘密鍵と公開鍵（カギペア／ヒミツカギ・コウカイカギ）

- **一言**: 必ず対で使う 2 つの鍵で、公開鍵は配ってよく秘密鍵は渡しません。
- **たとえ**: 誰でも投函できる郵便受け（公開鍵）と、それを開けられる唯一の鍵（秘密鍵）の関係です。
- **くわしく**: 同時に作られる 2 つの鍵で、公開鍵で確かめられる署名は、対の秘密鍵からしか作れません。SSH では公開鍵を接続先に置き、秘密鍵は自分の端末に厳重に保管します。秘密鍵にはパスフレーズ（鍵を使うための合い言葉）を付けられ、鍵のファイルが漏れたときの保険になります。
- **覚え方**: 公開鍵は「配ってよい南京錠」、秘密鍵は「1 本しかない合い鍵」と覚えます。
- **まちがえやすい**: 秘密鍵をサーバーに置いたり、チャットで送ったりするのは重大な事故です。人に渡してよいのは公開鍵（`.pub` が付いたファイル）だけです。
- **関連語**: [SSH の公開鍵認証](#g-net2-ssh-public-key-auth) / [SSH](#g-net2-ssh) / [known_hosts とホスト鍵](#g-net2-known-hosts)
- **確かめかた**: `ls -l ~/.ssh` で鍵の一覧と権限を、`ssh-keygen -l -f ~/.ssh/id_ed25519.pub` で鍵の指紋を確認できます（ファイル名は環境によって異なります）。

<a id="g-net2-scp-sftp"></a>
## SCP と SFTP（エス・シー・ピー と エス・エフ・ティー・ピー）

- **一言**: SSH の安全な通り道を使って、ファイルを送受信する方法です。
- **たとえ**: SCP は宅配便で箱を 1 つ送る作業、SFTP は倉庫に入って棚を見ながら出し入れする作業です。
- **くわしく**: どちらも SSH の上で動くので、追加でポートを開ける必要は基本的にありません。SCP はコマンド 1 回でコピーする単純な転送、SFTP は一覧表示や削除もできる対話的な操作に向きます。近年は SFTP を使う流れですが、方針は環境によって異なります。
- **覚え方**: SCP は「安全な cp（コピー）」、SFTP は「安全な FTP」で、頭の S は SSH の S です。
- **まちがえやすい**: SFTP は FTP とも FTPS（FTP に暗号化を足したもの）とも別物で、SSH の中で動く独自の仕組みです。名前が似ているので、事業者との受け渡しの方式を取り違えないようにします。
- **関連語**: [SSH](#g-net2-ssh) / [Telnet と FTP](#g-net2-telnet-ftp) / [鍵ペア](#g-net2-key-pair)
- **確かめかた**: `sftp user@example.com` で接続し、`pwd` と `ls` で中身を見て `quit` で抜けます。

<a id="g-net2-telnet-ftp"></a>
## Telnet と FTP：平文の危険（テルネット と エフ・ティー・ピー）

- **一言**: 中身を暗号化せずに流す古い接続方式で、盗み見にとても弱いです。
- **たとえ**: 郵便はがきです。書いた内容が、配達の途中で誰にでも読めてしまいます。
- **くわしく**: Telnet は遠隔操作、FTP はファイル転送に長く使われてきましたが、どちらも ID とパスワードを含めて平文（暗号化されない文字のまま）で流れます。そのため業務では SSH と SFTP に置き換えるのが原則です。ただし `telnet example.com 443` の形は、そのポートに届くかを調べる確認道具としては今も使えます。
- **覚え方**: 「T と F は平文、S が付けば暗号化」と対にして覚えます。
- **まちがえやすい**: 社内ネットワークだから平文でも安全、とは言えません。同じ回線につながっている相手からは中身が読めます。
- **関連語**: [SSH](#g-net2-ssh) / [SCP と SFTP](#g-net2-scp-sftp) / [VPN](#g-net2-vpn)
- **確かめかた**: `nc -zv example.com 443` や `telnet example.com 443` で、そのポートに届くかどうかだけを確認できます（どちらも入っていない環境があります）。

<a id="g-net2-vpn"></a>
## VPN（ブイ・ピー・エヌ）

- **一言**: 公衆の回線の中に、暗号化した専用トンネルを作る仕組みです。
- **たとえ**: 公道の上に、自分たちだけが通れる幌つきの通路を敷くようなものです。外から中身は見えません。
- **くわしく**: 拠点と拠点、あるいは自宅の PC と社内ネットワークを、インターネット越しに安全につなぎます。つないでいる間は、社内にいるのと同じようにサーバーへ届くようになります。管理画面などを外に公開せず、VPN の内側だけに置く運用がよく取られます。
- **覚え方**: Virtual Private Network は「仮想の専用線」で、借りた道に幌をかけると覚えます。
- **まちがえやすい**: VPN につながっても、社内側で許可されていない通信は通りません。「VPN がつながる」ことと「目的のサーバーに入れる」ことは別です。
- **関連語**: [プロキシ](#g-net2-proxy) / [踏み台サーバー](#g-net2-bastion) / [SSH](#g-net2-ssh)
- **確かめかた**: 接続の前後で `ip addr` を見比べ、トンネル用のネットワーク機器（インターフェース）が増えているかを確認します。

<a id="g-net2-proxy"></a>
## プロキシ

- **一言**: 通信を代わりに受け渡しして、記録や制限もできる中継役です。
- **たとえ**: 会社の受付です。外からの取り次ぎも、外へのお使いも、いったん受付を通します。
- **くわしく**: 社内から外へ出る通信をまとめる forward proxy と、外からの通信を受けて内部のサーバーへ渡す reverse proxy（リバースプロキシ）があります。アクセスの記録、行き先の制限、暗号化処理の肩代わりなどを担います。プロキシを通す環境では、`http_proxy` や `no_proxy` といった環境変数の設定が必要になることがあります。
- **覚え方**: proxy は代理人で、「自分では行かず、受付に行ってもらう」と覚えます。
- **まちがえやすい**: プロキシ経由だと、サーバー側のログに残るのはプロキシの IP アドレスです。利用者の IP アドレスを知りたいときは、`X-Forwarded-For` のような転送されたヘッダーを確認する必要があります。
- **関連語**: [VPN](#g-net2-vpn) / [踏み台サーバー](#g-net2-bastion) / [ポート番号](#g-net2-port-number)
- **確かめかた**: `env | grep -i proxy` で、プロキシ用の環境変数が設定されているかを確認します。

<a id="g-net2-bastion"></a>
## 踏み台サーバー・bastion（フミダイサーバー／バスティオン）

- **一言**: 内部のサーバーへ入る前に、必ず経由させる玄関口のサーバーです。
- **たとえ**: マンションのオートロックの入口です。まず入口で本人確認をして、そこから各部屋へ向かいます。
- **くわしく**: 内部のサーバーを直接インターネットに出さず、SSH の入口を 1 台に絞る構成です。入口が 1 か所なら、監視・記録・権限の管理をまとめて行えます。SSH には踏み台を経由して奥へ入る `ProxyJump` の機能があり、`ssh -J bastion.example.com target.example.com` の形で使えます。
- **覚え方**: bastion は城の見張り台（とりで）で、「まず門番のところを通る」と覚えます。
- **まちがえやすい**: 踏み台に秘密鍵を置く運用は危険です。鍵は自分の端末に置いたまま、`ProxyJump` で奥のサーバーへつなぎます。
- **関連語**: [SSH](#g-net2-ssh) / [VPN](#g-net2-vpn) / [SSH ポートフォワーディング](#g-net2-ssh-port-forwarding)
- **確かめかた**: `cat ~/.ssh/config` で、`ProxyJump` の設定が入っているかを確認します。

<a id="g-net2-known-hosts"></a>
## known_hosts とホスト鍵（ノウン・ホスツ と ホストカギ）

- **一言**: 接続先サーバーの身元を控えて、なりすましを見抜くための仕組みです。
- **たとえ**: 初対面で名刺を受け取って控えておき、次からは相手と名刺が合うかを確かめる作業です。
- **くわしく**: サーバーは自分のホスト鍵（サーバー自身の公開鍵）を示し、つなぐ側は `~/.ssh/known_hosts` に控えます。2 回目以降は控えと照合し、食い違えば警告を出して接続を止めます。初回に表示される指紋は、本来は別の手段で正しさを確かめてから受け入れます。
- **覚え方**: known_hosts は「知っている相手の控え帳」で、初回だけ名刺交換をすると覚えます。
- **まちがえやすい**: 警告が出たときに、中身を読まずに控えを消してつなぎ直すのは危険です。サーバーを作り直しただけなのか、別の相手につながっているのかを先に確かめます。
- **関連語**: [SSH](#g-net2-ssh) / [鍵ペア](#g-net2-key-pair) / [SSH の公開鍵認証](#g-net2-ssh-public-key-auth)
- **確かめかた**: `ssh-keygen -F example.com` で、そのホストの控えが登録済みかを確認できます。

<a id="g-net2-ssh-port-forwarding"></a>
## SSH ポートフォワーディング（エス・エス・エイチ・ポートフォワーディング）

- **一言**: SSH の通り道を借りて、別の通信を安全に運ぶ仕組みです。
- **たとえ**: 会社の社員通路を通って、外からは直接入れない部屋の窓口まで行くようなものです。
- **くわしく**: 手元の PC のポートを、SSH の接続先から見えるサーバーのポートにつなぎます。`ssh -L 8080:target.example.com:80 bastion.example.com` と書くと、手元の 8080 番へのアクセスが目的のサーバーの 80 番へ運ばれます。外に公開したくない管理画面などへ、一時的につなぐときに使います。
- **覚え方**: `-L` は Local の L で、手元の番号を先に書くと覚えます。
- **まちがえやすい**: 手元の番号と接続先の番号を逆に書く間違いが多いです。`-L 手元の番号:相手の名前:相手の番号` の順だと覚えます。
- **関連語**: [SSH](#g-net2-ssh) / [踏み台サーバー](#g-net2-bastion) / [ポート番号](#g-net2-port-number)
- **確かめかた**: 転送を張った状態で `ss -ltn` を実行し、手元に指定した番号が待ち受けているかを確認します。
