# 4. Linux のファイル・ユーザー・パッケージ

[用語集の入口](README.md) / [さくいん](index.md) / [前: OS とプロセスの基礎](03-os-process.md) / [次: ネットワークの基礎](05-network-basics.md)

この章では、サーバーに入って毎日触る「ファイル・権限・ソフトの入れ方」の言葉を集めました。どれも作業画面に必ず出てくるので、意味と確かめかたをセットで覚えてください。

> **この章で最初に押さえる 3 語**: パーミッション ／ sudo ／ パッケージマネージャー

<a id="g-linux-filesystem"></a>
## ファイルシステム

- **一言**: ディスクを、ファイルとディレクトリの形で使えるようにする仕組みです。
- **たとえ**: まっさらな倉庫に棚と番号札を入れて、物を出し入れできるようにした状態です。棚が無いままでは、荷物を置いても探し出せません。
- **くわしく**: ディスクはそのままでは「ただの広い記録場所」です。ファイルシステムを作る（フォーマットする）と、名前・サイズ・更新日時・置き場所を管理する台帳ができます。Linux では ext4 や XFS がよく使われ、種類によって得意なことが変わります。
- **覚え方**: 「ディスクは空き地、ファイルシステムはそこに棚を並べた倉庫」と覚えます。
- **まちがえやすい**: フォーマットは「掃除」ではなく「棚の作り直し」です。中のデータは使えなくなるので、状態を見るだけの確認作業とは切り分けて考えます。
- **関連語**: [パーティション](#g-linux-partition) ／ [マウントとアンマウント](#g-linux-mount) ／ [inode](#g-linux-inode)
- **確かめかた**: `df -T` でいま使っているファイルシステムの種類が見えます。`lsblk -f` でも確認できます。

<a id="g-linux-directory-tree"></a>
## ディレクトリ階層（ディレクトリカイソウ）

- **一言**: すべてのファイルを、/ を頂点とする 1 本の木の形に並べる決まりです。
- **たとえ**: 1 棟のマンションです。/ が建物の入口、/etc は管理人室、/var は日報がたまる書庫、/home は住人の部屋にあたります。
- **くわしく**: Linux にはドライブレター（C ドライブのような記号）が無く、どの装置の中身も / の下のどこかに現れます。置き場所の役割はだいたい決まっていて、/etc は設定ファイル、/var はログのように増減するデータ、/home は一般ユーザーの個人領域です。/usr はインストール済みのプログラム本体、/tmp は一時ファイル、/opt は後から入れた追加ソフトの置き場です。慣習どおりに置くと、初めて見る人でも当たりを付けられます。
- **覚え方**: まずは「設定は etc、変わるものは var、人は home、本体は usr」の 4 つを覚えます。
- **まちがえやすい**: /tmp は再起動などで中身が消えることがある置き場です。作業の途中結果を置いたまま帰ると、翌日には無いことがあります。
- **関連語**: [絶対パスと相対パス](#g-linux-path) ／ [ログファイルと /var/log](#g-linux-log-var-log) ／ [マウントとアンマウント](#g-linux-mount)
- **確かめかた**: `ls /` で最上位の一覧、`ls /etc | head` で設定ファイルの並びが見えます。

<a id="g-linux-path"></a>
## 絶対パスと相対パス（ゼッタイパス／ソウタイパス）

- **一言**: 絶対パスは / から書く住所、相対パスは今いる場所からの道順です。
- **たとえ**: 絶対パスは「東京都◯◯区 1-2-3」という住所、相対パスは「ここから 2 つ隣のビル」という道案内です。道案内は、自分の立ち位置が変わると別の場所を指します。
- **くわしく**: 絶対パスは必ず / で始まり、どこから実行しても同じ場所を指します。相対パスは今いるディレクトリが起点で、. が現在地、.. が 1 つ上を表します。自動実行の仕組みでは起点が思っている場所と違うことが多いので、設定やスクリプトには絶対パスで書くのが安全です。
- **覚え方**: 「/ で始まれば絶対、始まらなければ相対」と、先頭の 1 文字で見分けます。
- **まちがえやすい**: 手で打つと動くのに cron（決まった時刻に自動実行する仕組み）から動かない原因の多くは、相対パスと起点のずれです。
- **関連語**: [カレントディレクトリ](#g-linux-cwd) ／ [ディレクトリ階層](#g-linux-directory-tree) ／ [cron と systemd timer](#g-linux-cron-timer)
- **確かめかた**: `pwd` で現在地、`ls ..` で 1 つ上の一覧、`ls -l /etc/hosts` で絶対パス指定の動きが確かめられます。

<a id="g-linux-cwd"></a>
## カレントディレクトリ

- **一言**: シェルでいま自分が立っている、作業中のディレクトリです。
- **たとえ**: 地図アプリの現在地ピンです。ピンの位置が違えば、同じ「2 つ先を右」でも着く場所が変わります。
- **くわしく**: コマンドにパスを書かないとき、その対象はカレントディレクトリから探されます。`cd` で移動し、`pwd` で現在地を表示します。プロンプト（入力待ちの表示）に現在地が出る設定が多く、~ はホームディレクトリを表します。
- **覚え方**: `pwd` は print working directory の頭文字で、「今どこ？」を聞く合言葉だと覚えます。
- **まちがえやすい**: `cd` の効果は、いま打っている端末（ターミナル）の中だけに残ります。スクリプトの中で移動しても、終わったあとの端末の現在地は元のままです。
- **関連語**: [絶対パスと相対パス](#g-linux-path) ／ [ディレクトリ階層](#g-linux-directory-tree)
- **確かめかた**: `pwd` を打ち、`cd /etc` の後にもう一度 `pwd` を打つと、現在地の変化が見えます。

<a id="g-linux-dotfile"></a>
## 隠しファイル（カクシファイル）

- **一言**: 名前が . で始まり、ふだんの一覧には出てこないファイルです。
- **たとえ**: 机の引き出しにしまった個人メモです。机の上（`ls`）には出ませんが、引き出しを開ければ（`ls -a`）ちゃんとあります。
- **くわしく**: ドットで始まる名前は一覧に出さない、という昔からの約束で、ドットファイルとも呼ばれます。ホームディレクトリには .bashrc（シェルの設定）や .ssh（鍵の置き場）など、個人向けの設定が並びます。書き換えたり消したりすると、次にログインしたときの動きが変わります。
- **覚え方**: 「ドットで始まると見えないだけで、消えてはいない」と覚え、`ls -a` の a は all だと結び付けます。
- **まちがえやすい**: 隠しファイルはセキュリティの機能ではありません。見えないだけで、権限のある人には普通に読めます。
- **関連語**: [パーミッション](#g-linux-permission) ／ [設定ファイルとバックアップ](#g-linux-config-backup) ／ [ディレクトリ階層](#g-linux-directory-tree)
- **確かめかた**: `ls -a ~` で自分のホームの隠しファイルが並びます。`ls -la ~` なら権限も一緒に見えます。

<a id="g-linux-permission"></a>
## パーミッション

- **一言**: 誰がそのファイルを読み・書き・実行できるかを決める設定です。
- **たとえ**: 部屋の鍵の配り方です。持ち主・同じ班の人・それ以外の 3 組に、「見る・書き換える・入る」の鍵を渡すかどうかを決めます。
- **くわしく**: r が読み取り、w が書き込み、x が実行です。所有者・グループ・その他の順に 3 つずつ並び、`ls -l` では rwxr-xr-x のように表示されます。数字では r が 4、w が 2、x が 1 で、足した値を 3 桁並べます。755 なら所有者が 7（rwx）、グループとその他が 5（r-x）という意味です。
- **覚え方**: 「読む 4、書く 2、走る 1」で、足して 7 なら全部入り、5 は読みと実行だけです。
- **まちがえやすい**: ディレクトリでは意味が変わり、x は「中に入る」、r は「中身の一覧を見る」です。動かないからと 777 にするのは、玄関の鍵を外すのと同じで解決になりません。
- **関連語**: [所有者とグループ](#g-linux-owner-group) ／ [root](#g-linux-root) ／ [隠しファイル](#g-linux-dotfile)
- **確かめかた**: `ls -l /etc/hosts` で rwx の並びを確認し、`stat /etc/hosts` なら 0644 のような数字でも見えます。

<a id="g-linux-owner-group"></a>
## 所有者とグループ（ショユウシャ／グループ）

- **一言**: ファイルごとに決まっている、持ち主と担当チームのことです。
- **たとえ**: 会議室の管理台帳です。「持ち主は佐藤さん、使えるのは総務チーム、他の人は見るだけ」と決めておくイメージです。
- **くわしく**: すべてのファイルに、ユーザー（持ち主）とグループ（チーム）が 1 つずつ結び付いています。パーミッションは、この 3 区分（所有者・グループ・その他）ごとに効きます。同じファイルを複数人で扱うときは、全員を同じグループに入れ、グループの権限で共有するのが定番です。
- **覚え方**: `chmod` で使う u は user（持ち主）、g は group（チーム）、o は others（その他）の頭文字です。
- **まちがえやすい**: グループに追加してもらっても、ログイン中のセッションにはすぐ反映されません。いったんログインし直すと有効になります。
- **関連語**: [パーミッション](#g-linux-permission) ／ [一般ユーザー](#g-linux-normal-user) ／ [root](#g-linux-root)
- **確かめかた**: `ls -l` の 3 列目が所有者、4 列目がグループです。`id` と `groups` で自分の所属が分かります。

<a id="g-linux-root"></a>
## root（ルート）

- **一言**: サーバーの中で何でもできる、いちばん強い管理者ユーザーです。
- **たとえ**: 建物のマスターキーを持つ管理人です。どの部屋にも入れる代わりに、間違えたときの被害も一番大きくなります。
- **くわしく**: root はユーザー ID が 0 の特別なユーザーで、パーミッションの制限をほとんど受けません。ソフトの導入、設定ファイルの変更、サービスの起動などに必要になります。危険が大きいので、普段は一般ユーザーで作業し、必要なときだけ sudo で権限を借りるのが基本です。
- **覚え方**: 「root はマスターキー、持つのは必要な一瞬だけ」と覚えます。
- **まちがえやすい**: 「ルート」は 3 つあり、管理者の root、階層の頂点の /、root 専用の個人領域の /root を指します。話が噛み合わないときは、どのルートのことかを確かめます。
- **関連語**: [一般ユーザー](#g-linux-normal-user) ／ [sudo](#g-linux-sudo) ／ [su](#g-linux-su)
- **確かめかた**: `id -u` の結果が 0 なら root です。`whoami` でも今のユーザー名が分かります。

<a id="g-linux-normal-user"></a>
## 一般ユーザー（イッパンユーザー）

- **一言**: 自分の持ち物だけを扱える、権限が限られた普段使いのユーザーです。
- **たとえ**: 自分の部屋の鍵しか持っていない住人です。共用部の工事は、そのつど管理人に頼みます。
- **くわしく**: ふだんのログインと作業は一般ユーザーで行います。書き込めるのは自分のホーム（/home/ユーザー名）や許可された場所だけなので、打ち間違えても被害が広がりにくくなります。人ごとにユーザーを分けておくと、誰がいつ何をしたかをログから追えます。
- **覚え方**: 「普段は住人、工事のときだけ管理人（root）」と覚えます。
- **まちがえやすい**: 全員で 1 つのアカウントを共有すると、作業者を後から特定できなくなります。
- **関連語**: [root](#g-linux-root) ／ [sudo](#g-linux-sudo) ／ [所有者とグループ](#g-linux-owner-group)
- **確かめかた**: `whoami` で今の自分、`id` で所属グループ、`ls -ld ~` で自分のホームの権限が見えます。

<a id="g-linux-sudo"></a>
## sudo（スードゥー）

- **一言**: 1 つのコマンドだけを管理者の権限で実行するための命令です。
- **たとえ**: 受付でマスターキーを一時的に借りる手続きです。誰がいつ何のために借りたかが、そのつど記録に残ります。
- **くわしく**: コマンドの先頭に付けると、そのコマンドだけが root の権限で動きます。誰が何を実行できるかは、/etc/sudoers や /etc/sudoers.d 以下の設定で決まります。既定では実行した内容がログに残るので、root で入りっぱなしにするより後から追いやすくなります。
- **覚え方**: super user do は「管理者として、これをやって」という意味だと覚えます。
- **まちがえやすい**: 効くのは直後のコマンド 1 つだけです。`sudo コマンド > /etc/ファイル` と書くと、書き込みは元の権限のまま行われて失敗します。
- **関連語**: [root](#g-linux-root) ／ [su](#g-linux-su) ／ [一般ユーザー](#g-linux-normal-user)
- **確かめかた**: `sudo -l` で、自分に許可されているコマンドの一覧が見えます（パスワードを聞かれることがあります）。

<a id="g-linux-su"></a>
## su（エス・ユー）

- **一言**: 今の端末で、別のユーザーに切り替わるコマンドです。
- **たとえ**: 制服を着替えて別の担当者になりきる作業です。着替えたままなので、脱ぐ（`exit`）までは、ずっとその人の権限で動きます。
- **くわしく**: `su - ユーザー名` のように使い、切り替え先のパスワードを入力します。- を付けると、そのユーザーでログインし直したのと同じ状態になり、環境変数やカレントディレクトリも切り替わります。`exit` で元のユーザーに戻ります。環境によっては root にパスワードが設定されておらず、`su` で root になれないこともあります。
- **覚え方**: 「sudo は 1 回だけ借りる、su は着替えて居座る」と対で覚えます。
- **まちがえやすい**: 聞かれるパスワードは、sudo なら自分のもの、su なら切り替え先のものです。また `su` と `su -` は別物で、- が無いと PATH（コマンドの探索先）が前のまま残り、コマンドが見つからないことがあります。
- **関連語**: [sudo](#g-linux-sudo) ／ [root](#g-linux-root) ／ [一般ユーザー](#g-linux-normal-user)
- **確かめかた**: 切り替えた先で `whoami` と `echo $PATH` を打つと、今が誰で探索先がどう変わったかが分かります（`exit` で戻れます）。

<a id="g-linux-package"></a>
## パッケージ

- **一言**: ソフト本体と設定や導入手順を 1 つにまとめた、配布用の箱です。
- **たとえ**: 組み立て済みの家具が、説明書ごと 1 箱で届くイメージです。自分で木を切って作る（ソースから作る）必要がありません。
- **くわしく**: 中にはプログラム本体、初期設定ファイル、必要な相手（依存）の情報、導入の前後に走る処理などが入っています。Debian や Ubuntu 系では .deb、Red Hat 系では .rpm という形式が使われます。パッケージで入れると、どのファイルがどこに置かれたかを後から一覧できます。
- **覚え方**: 「パッケージは説明書つきの箱」で、中身だけでなく置き場所の指示も入っていると覚えます。
- **まちがえやすい**: 同じソフトでも、パッケージで入れたものと自分で作って入れたものは別管理です。混ぜると、更新や削除のときにどちらが動いているのか分からなくなります。
- **関連語**: [パッケージマネージャー](#g-linux-package-manager) ／ [リポジトリ](#g-linux-repository) ／ [依存関係](#g-linux-dependency)
- **確かめかた**: `dpkg -l | head`（Debian 系）や `rpm -qa | head`（Red Hat 系）で、入っているパッケージが一覧できます。

<a id="g-linux-package-manager"></a>
## パッケージマネージャー

- **一言**: パッケージの検索・導入・更新・削除をまとめて行う道具です。
- **たとえ**: スマホのアプリストアです。名前で探して入れれば、必要な部品も一緒に揃えてくれます。
- **くわしく**: Debian や Ubuntu 系では apt、Red Hat 系（RHEL、Rocky、Fedora など）では dnf を使います。どちらもリポジトリ（配布元）から取ってきて、依存関係を自動で解決し、入れたものを台帳で管理します。役割は同じでコマンド名が違うだけ、と考えると覚えやすいです。
- **覚え方**: 「Debian 系は apt、Red Hat 系は dnf」と、系統とセットで覚えます。
- **まちがえやすい**: `apt update` はカタログ（入手できるパッケージの一覧）を新しくするだけで、ソフト本体は更新されません。本体の更新は `apt upgrade` です。
- **関連語**: [パッケージ](#g-linux-package) ／ [リポジトリ](#g-linux-repository) ／ [依存関係](#g-linux-dependency)
- **確かめかた**: `apt list --installed | head` や `dnf list installed | head` で導入済みの一覧が見えます。どちらが使えるかは環境によって異なります。

<a id="g-linux-repository"></a>
## リポジトリ

- **一言**: パッケージが置いてある配布元と、その品揃えのことです。
- **たとえ**: アプリストアの棚そのものです。棚に載っていない商品は、店員（apt や dnf）に頼んでも出てきません。
- **くわしく**: どの配布元を見るかは設定ファイルで決まります。置き場所は、Debian 系が /etc/apt 以下、Red Hat 系が /etc/yum.repos.d です。多くは電子署名を使って、正しい配布元から届いたものかを検証してから取り込みます。標準の棚に無いソフトが必要なときは、追加のリポジトリを登録することがあります。
- **覚え方**: 「リポジトリは棚、パッケージは商品、apt と dnf は店員」の 3 点セットで覚えます。
- **まちがえやすい**: Git のリポジトリ（ソースコードの保管庫）とは別物です。会話では「パッケージのリポジトリ」と言い分けると混乱しません。
- **関連語**: [パッケージ](#g-linux-package) ／ [パッケージマネージャー](#g-linux-package-manager) ／ [依存関係](#g-linux-dependency)
- **確かめかた**: Debian 系は `ls /etc/apt/sources.list.d`、Red Hat 系は `dnf repolist` で、いま見ている配布元が確認できます（ファイルの置き方は環境によって異なります）。

<a id="g-linux-dependency"></a>
## 依存関係（イゾンカンケイ）

- **一言**: そのソフトが動くために必要な、別のソフトや部品のつながりです。
- **たとえ**: プリンタを買ったらインクとケーブルも要る、という関係です。どれか 1 つ欠けると印刷できません。
- **くわしく**: 多くのソフトは、共通のライブラリ（部品の集まり）を借りて動いています。パッケージには「これが必要」という情報が書かれていて、パッケージマネージャーが足りない分を自動で入れてくれます。逆に、他から必要とされているものを消そうとすると警告が出ます。
- **覚え方**: dependency の depend は「ぶら下がる」で、ぶら下がる先を外すと落ちる、と覚えます。
- **まちがえやすい**: 一緒に入ったものを「使っていないから」と個別に消すと、本体まで動かなくなることがあります。
- **関連語**: [パッケージ](#g-linux-package) ／ [パッケージマネージャー](#g-linux-package-manager) ／ [リポジトリ](#g-linux-repository)
- **確かめかた**: `apt-cache depends パッケージ名` や `rpm -qR パッケージ名` で、必要な相手が一覧できます。

<a id="g-linux-partition"></a>
## パーティション

- **一言**: 1 台のディスクを、用途ごとに区切って作る領域のことです。
- **たとえ**: 広いワンルームを間仕切りで分けるようなものです。片方が荷物で埋まっても、もう片方までは埋まりません。
- **くわしく**: 区切っておくと、たとえばログが増え続けても、システム本体の領域まで満杯にせずに済みます。よくあるのは、起動用の /boot、本体の /、そして swap（メモリが足りないときの逃がし先）という組み合わせです。区切りの管理形式には MBR と GPT があり、近年は GPT が主流です。
- **覚え方**: 「区切る（パーティション）、棚を作る（ファイルシステム）、つなぐ（マウント）」の 3 段で覚えます。
- **まちがえやすい**: 区切っただけでは使えません。ファイルシステムを作り、マウントして初めてファイルが置けます。
- **関連語**: [ファイルシステム](#g-linux-filesystem) ／ [マウントとアンマウント](#g-linux-mount) ／ [LVM](#g-linux-lvm)
- **確かめかた**: `lsblk` でディスクと区切りが木の形で見えます。`lsblk -f` なら種類やラベルも出ます。

<a id="g-linux-mount"></a>
## マウントとアンマウント

- **一言**: 記憶領域をディレクトリにつないで使える状態にすること、外すことです。
- **たとえ**: 増築した部屋に廊下をつなぐ作業です。つなぐ先のドア（マウントポイント）を決めないと、部屋があっても入れません。
- **くわしく**: Linux ではドライブレターの代わりに、パーティションを /data のようなディレクトリに割り当てて使います。この割り当てがマウント、外すのがアンマウントです。アンマウントは、その中のファイルを誰かが使っていると失敗します。
- **覚え方**: 外すほうは un が付くと覚え、コマンド名は n が 1 つ落ちて `umount` になる点も一緒に押さえます。
- **まちがえやすい**: すでにファイルが入っているディレクトリにマウントすると、元のファイルは見えなくなります。消えたのではなく、下に隠れているだけです。
- **関連語**: [パーティション](#g-linux-partition) ／ [fstab](#g-linux-fstab) ／ [ファイルシステム](#g-linux-filesystem)
- **確かめかた**: `df -h` でマウント先と空き、`findmnt` なら親子関係まで見えます。

<a id="g-linux-fstab"></a>
## fstab（エフエスタブ）

- **一言**: 起動時に何をどこへマウントするかを書いた設定ファイルです。
- **たとえ**: 引っ越し先での「この荷物はこの部屋へ」という指示書です。毎回言わなくても、起動のたびに同じ配置になります。
- **くわしく**: 場所は /etc/fstab で、1 行に「対象の装置・マウント先・ファイルシステムの種類・オプション」などを並べます。対象は、名前が変わりにくい UUID（装置ごとに割り振られた固有の番号）で書くのが安全です。手でマウントした状態は再起動で消えるので、ずっと使う設定はここに書きます。
- **覚え方**: file system table の略で、意味はそのまま「ファイルシステムの一覧表」です。
- **まちがえやすい**: 書き間違えたまま再起動すると、起動が途中で止まってしまうことがあります。編集前のバックアップと、書き方の検証はセットで行います。
- **関連語**: [マウントとアンマウント](#g-linux-mount) ／ [パーティション](#g-linux-partition) ／ [設定ファイルとバックアップ](#g-linux-config-backup)
- **確かめかた**: `cat /etc/fstab` で中身、`lsblk -f` で UUID が見えます。`findmnt --verify` で書き方の検証もできます（使えるかは環境によって異なります）。

<a id="g-linux-lvm"></a>
## LVM（エル・ブイ・エム）

- **一言**: ディスクをまとめて、後から自由に切り出せるようにする仕組みです。
- **たとえ**: 複数の水源（PV）を 1 つの貯水池（VG）に集め、そこから必要な太さの水道管（LV）を引くイメージです。
- **くわしく**: PV（物理ボリューム）は、実際のディスクやパーティションのことです。それをまとめた入れ物が VG（ボリュームグループ）、VG から切り出して実際に使う領域が LV（論理ボリューム）です。ファイルシステムは LV の上に作ります。容量が足りなくなったら、VG に PV を足して LV を広げられるのが大きな利点です。
- **覚え方**: 「PV を集めて VG、VG から切って LV」と、下から上へ積む順で覚えます。
- **まちがえやすい**: LV を広げただけでは、使える容量は増えて見えません。その上に載っているファイルシステムを広げる作業も必要です。
- **関連語**: [パーティション](#g-linux-partition) ／ [ファイルシステム](#g-linux-filesystem) ／ [マウントとアンマウント](#g-linux-mount)
- **確かめかた**: `sudo pvs`、`sudo vgs`、`sudo lvs` で 3 段の状態が表で見えます。LVM を使っていない環境では、何も出ないことがあります。

<a id="g-linux-inode"></a>
## inode（アイノード）

- **一言**: ファイルの属性と置き場所を記録した、1 ファイル 1 枚の管理札です。
- **たとえ**: 図書館の蔵書カードです。カードには大きさ・持ち主・棚の位置が書いてあり、タイトル（ファイル名）は別の索引に載っています。
- **くわしく**: inode にはサイズ、所有者、パーミッション、更新日時、データの位置が入ります。ファイル名は inode の中ではなく、ディレクトリが持つ「名前と inode 番号の対応表」に書かれています。ext4 などでは、inode の数をファイルシステムを作るときに決めます（XFS のように後から増やせる方式もあります）。そのため、小さなファイルを大量に作ると、容量が余っていても inode が先に尽きることがあります。
- **覚え方**: 「名前は表札、inode は中身の台帳」と分けて覚えます。
- **まちがえやすい**: 空き容量があるのにファイルが作れないときは、inode 切れを疑います。`df -h` だけを見ていても気づけません。
- **関連語**: [ファイルシステム](#g-linux-filesystem) ／ [シンボリックリンク](#g-linux-symlink) ／ [ハードリンク](#g-linux-hardlink)
- **確かめかた**: `ls -i` で番号、`df -i` で inode の使用状況、`stat ファイル名` で属性がまとめて見えます。

<a id="g-linux-symlink"></a>
## シンボリックリンク

- **一言**: 別のファイルの場所を指し示す、道しるべ専用のファイルです。
- **たとえ**: 「この本は 3 階の書庫にあります」と書いた案内札です。札は本そのものではないので、本が動くと案内は行き止まりになります。
- **くわしく**: `ln -s` で作り、中身は「相手のパス」だけです。長いパスに短い名前を付けたり、版ごとのディレクトリを current のような固定名で指したりするのに使います。`ls -l` では行の先頭が l になり、矢印で相手が表示されます。別のファイルシステムをまたいで指せるのは、この形式だけです。
- **覚え方**: -s は symbolic の s で、s が付けば案内板、付かなければ表札（ハードリンク）と覚えます。
- **まちがえやすい**: 相手を消したり移動したりすると、リンクだけが残って行き先が無くなります（リンク切れ）。`ln -s` は「本体、新しく作る名前」の順に書くので、逆にすると思わぬ場所にリンクができます。
- **関連語**: [ハードリンク](#g-linux-hardlink) ／ [inode](#g-linux-inode) ／ [絶対パスと相対パス](#g-linux-path)
- **確かめかた**: `ls -l /usr/bin | grep '^l' | head` で矢印付きの行が見えます。`readlink -f パス` なら最終的な行き先が分かります。

<a id="g-linux-hardlink"></a>
## ハードリンク

- **一言**: 同じ実体（inode）に、もう 1 つ名前を付けたものです。
- **たとえ**: 1 つの部屋に表札を 2 枚出すようなものです。どちらの表札から入っても、同じ部屋にたどり着きます。
- **くわしく**: `ln` を -s なしで使うと作れます。名前が増えるだけで中身の複製は作られないため、容量はほとんど増えません。片方の名前を消しても、もう片方が残っていればファイルは生き続けます。
- **覚え方**: 「ハードは表札の追加、シンボリックは案内板の設置」と対で覚えます。
- **まちがえやすい**: 同じファイルシステムの中でしか作れず、ふつうディレクトリには作れません。実体は 1 つなので、バックアップのつもりで作っても、書き換えは両方の名前に反映されます。
- **関連語**: [シンボリックリンク](#g-linux-symlink) ／ [inode](#g-linux-inode) ／ [ファイルシステム](#g-linux-filesystem)
- **確かめかた**: `ls -li` で inode 番号とリンク数（3 列目）を見比べます。`stat ファイル名` の Links の値でも分かります。

<a id="g-linux-df-du"></a>
## df と du（ディー・エフ／ディー・ユー）

- **一言**: df は領域全体の空き、du はディレクトリごとの使用量を見る道具です。
- **たとえ**: df は倉庫全体の残りスペースの掲示、du は棚ごとに荷物の量を測る作業です。
- **くわしく**: df はマウントされた領域の単位で、容量・使用量・空き・使用率を表示します。du は指定した場所から下をたどって、実際に使っている量を積み上げます。容量が足りないときは、df で対象の領域を絞り、du で原因のディレクトリを探すのが定番の順番です。
- **覚え方**: df は全体の空き（disk free）、du は場所ごとの使用量（disk usage）と読み解きます。
- **まちがえやすい**: ファイルを消したのに df の空きが増えないことがあります。プログラムがそのファイルを開いたままだと、終了するまで領域が解放されないためです。
- **関連語**: [ファイルシステム](#g-linux-filesystem) ／ [マウントとアンマウント](#g-linux-mount) ／ [ログローテーション](#g-linux-logrotate)
- **確かめかた**: `df -h` で全体、`du -sh /var/log` でそのディレクトリ以下の合計が見えます（読めない場所ではエラーが出ます）。

<a id="g-linux-log-var-log"></a>
## ログファイルと /var/log

- **一言**: システムやアプリの動作記録と、それが集まる標準の置き場です。
- **たとえ**: 現場の作業日報です。トラブルのとき最初に読むのは、自分の記憶ではなく日報のほうです。
- **くわしく**: /var/log には、システム全体の記録や認証の記録、ソフトごとのディレクトリが並びます。名前は系統で違い、システム全体の記録は Debian 系が syslog、Red Hat 系が messages、認証の記録は auth.log や secure です。多くは後ろに書き足していくテキストなので、末尾から読むと最新の出来事が分かります。環境によっては、これらのファイルが無く journald だけで記録している場合もあります。
- **覚え方**: 「var は変わるもの、その代表がログ」と、/var/log をセットで覚えます。
- **まちがえやすい**: 中身は root や特定のグループしか読めないものが多く、権限エラーが出たら sudo を付けて読みます。
- **関連語**: [ログローテーション](#g-linux-logrotate) ／ [journald と journalctl](#g-linux-journald) ／ [ディレクトリ階層](#g-linux-directory-tree)
- **確かめかた**: `ls -l /var/log` で顔ぶれを見て、`sudo tail -n 50 /var/log/syslog` のように末尾だけ読みます（ファイル名は環境によって異なります）。

<a id="g-linux-grep-tail"></a>
## grep と tail -f（グレップ／テイル・エフ）

- **一言**: grep は目的の行を探し、tail -f は最新の行を見張る道具です。
- **たとえ**: grep は本の索引を引いて必要なページだけ抜き出す作業です。tail -f は日報の最後のページを開いたまま、書き足される様子を眺めることにあたります。
- **くわしく**: grep は、指定した文字を含む行だけを画面に出します。`grep error /var/log/syslog` のように、探す言葉と読むファイルを並べて使います。tail は末尾を表示するコマンドで、-f を付けると画面を開いたまま、新しく書き足された行が続けて流れます。作業する画面とは別に tail -f を出しておくと、失敗したその瞬間の記録をその場で読めます。
- **覚え方**: 「grep は探す、tail は末尾、-f は follow で追いかける」と 3 点で覚えます。
- **まちがえやすい**: tail -f は自分では終わらないので、見終わったら Ctrl + C で抜けます。grep は大文字と小文字を区別するため、Error と error は別の言葉として扱われます。
- **関連語**: [ログファイルと /var/log](#g-linux-log-var-log) ／ [journald と journalctl](#g-linux-journald) ／ [シェルスクリプト](#g-linux-shell-script)
- **確かめかた**: `grep -c . /etc/hosts` で行数、`tail -n 5 /etc/services` で末尾 5 行が見えます。`sudo tail -f /var/log/syslog` は流れる様子を確かめられます（ファイル名は環境によって異なります）。

<a id="g-linux-logrotate"></a>
## ログローテーション

- **一言**: ログを定期的に新しいファイルへ切り替え、古い分を整理する仕組みです。
- **たとえ**: 日報のノートを月ごとに新しくして、古いノートは倉庫へ、期限が来たら処分するのと同じです。
- **くわしく**: ログは放っておくと増え続け、いずれディスクを埋めます。logrotate という仕組みが、サイズや日数の条件でファイルを切り替え、名前を .1 や .gz に変えて世代として管理します。設定は /etc/logrotate.conf と、ソフトごとに置かれる /etc/logrotate.d にあります。
- **覚え方**: 「番号が大きいほど古い」と覚え、今のログが .1 に、.1 が .2 に押し出されると考えます。
- **まちがえやすい**: 決めた世代数を超えた古いログは自動で消えます。長く残したい記録は、別の場所へ退避する設計が必要です。
- **関連語**: [ログファイルと /var/log](#g-linux-log-var-log) ／ [df と du](#g-linux-df-du) ／ [cron と systemd timer](#g-linux-cron-timer)
- **確かめかた**: `ls /var/log` で .1 や .gz の付いた世代を確認し、`cat /etc/logrotate.conf` で既定の条件が読めます。

<a id="g-linux-journald"></a>
## journald と journalctl（ジャーナルディー／ジャーナルシーティーエル）

- **一言**: systemd がログを集めて保存する仕組みと、それを読み出すコマンドです。
- **たとえ**: 全部門の日報を 1 か所に集める本部（journald）と、条件を言えば必要な分だけ出してくれる窓口（journalctl）です。
- **くわしく**: journald は起動処理やサービスの出力をまとめて受け取り、テキストではなく専用の形式で保存します。そのため `cat` では読めず、journalctl を通して読みます。サービス単位や期間での絞り込み、重要度での抽出ができるのが強みです。
- **覚え方**: 末尾が d ならためる側のデーモン（待機し続けるプログラム）、ctl なら操作する側のコントロールと覚えます。
- **まちがえやすい**: 保存先が用意されていない環境では、ログがメモリ上にしか残らず、再起動で消えます。残したい場合は、永続保存の設定が必要です。
- **関連語**: [ログファイルと /var/log](#g-linux-log-var-log) ／ [ログローテーション](#g-linux-logrotate) ／ [cron と systemd timer](#g-linux-cron-timer)
- **確かめかた**: `journalctl -n 50` で直近 50 行、`journalctl -u サービス名 --since "1 hour ago"` で対象と期間を絞れます（権限によっては sudo が必要です）。

<a id="g-linux-cron-timer"></a>
## cron と systemd timer（クーロン／システムディー・タイマー）

- **一言**: 決めた時刻に処理を自動で実行する、2 つのやり方です。
- **たとえ**: cron は昔からある目覚まし時計、systemd timer は予定表と作業指示書を分けて持つスケジュール帳です。
- **くわしく**: cron は「分 時 日 月 曜日 コマンド」の 1 行で予定を書き、`crontab` で管理します。systemd timer は、いつ動かすかを書いた .timer と、何をするかを書いた .service の 2 つ 1 組で使います。実行の記録が journald に残るので、後から追いやすいのが利点です。
- **覚え方**: 「cron は 1 行、timer は 2 ファイル」と覚えます。
- **まちがえやすい**: cron が動かす環境は、ふだんログインしたときと環境変数が違い、PATH（コマンドの探索先）も短くなります。手では動くのに cron で失敗するときは、コマンドを絶対パスで書くと直ることが多いです。
- **関連語**: [絶対パスと相対パス](#g-linux-path) ／ [ログローテーション](#g-linux-logrotate) ／ [journald と journalctl](#g-linux-journald)
- **確かめかた**: `crontab -l` で自分の予定、`systemctl list-timers` で有効なタイマーと次回の実行時刻が見えます。

<a id="g-linux-shell-script"></a>
## シェルスクリプト

- **一言**: いつも打つコマンドを順番に書いて、まとめて実行できるファイルです。
- **たとえ**: 料理の手順書です。作るたびに思い出さなくても、書いてある順に進めれば毎回同じ味になります。
- **くわしく**: 1 行目に #!/bin/bash と書き、その下にふだん打つコマンドを上から順に並べます。この 1 行目はシバンと呼び、どのシェル（コマンドを受け付けるプログラム）に読ませるかの指定です。実行の権限を付けたうえで `./ファイル名` と打つと、書いた順に処理が進みます。決まった時刻に動かす cron から呼び出せば、点検やログの整理といった手順をそのまま自動化できます。
- **覚え方**: 「手で打つ順番をそのまま書いた台本」と考え、名前の末尾の .sh は shell の sh だと結び付けます。
- **まちがえやすい**: 作っただけでは動かず、実行の権限が無いと Permission denied と出ます。また cron から動かすときは環境変数が少ないので、コマンドを絶対パスで書くと安定します。
- **関連語**: [cron と systemd timer](#g-linux-cron-timer) ／ [パーミッション](#g-linux-permission) ／ [テキストエディタ](#g-linux-editor)
- **確かめかた**: `ls -l /etc/cron.daily` で用意されているスクリプトが並び、`head -n 5 /etc/cron.daily/logrotate` で 1 行目の書き方が読めます。`bash -n ファイル名` なら、実行せずに書き方だけ確かめられます（ファイル名は環境によって異なります）。

<a id="g-linux-editor"></a>
## テキストエディタ

- **一言**: サーバーの設定ファイルを画面上で直接書き換える道具です。
- **たとえ**: vi は慣れると速い職人の道具、nano は使い方が画面に書いてある初心者向けの道具です。
- **くわしく**: vi（ブイ・アイ）はほぼどのサーバーにも入っているので、最低限の操作を覚えておくと困りません。文字を入れるには i を押して挿入モードに入り、Esc で戻り、`:wq` で保存して終了、`:q!` で保存せずに終了します。nano（ナノ）は画面の下に操作案内が出るので、まずはこちらから始めても構いません。
- **覚え方**: 「vi は i で書き始め、Esc で戻り、: で命令」と覚えます。
- **まちがえやすい**: vi で文字が入らないのは、故障ではなくモードが違うからです。また、書き込み権限の無いファイルは、開けても保存できません。
- **関連語**: [設定ファイルとバックアップ](#g-linux-config-backup) ／ [パーミッション](#g-linux-permission) ／ [sudo](#g-linux-sudo)
- **確かめかた**: `vi -R /etc/hosts` と打つと読み取り専用で開けます（終了は `:q`）。nano があるかは `command -v nano` で分かります。

<a id="g-linux-config-backup"></a>
## 設定ファイルとバックアップ（セッテイファイル／バックアップ）

- **一言**: 動きを決めるファイルと、変更前に取っておくその写しのことです。
- **たとえ**: 契約書を書き直す前に、原本をコピーして金庫にしまうのと同じです。書き損じても、元の 1 枚があれば戻せます。
- **くわしく**: Linux の設定の多くは /etc 以下のテキストファイルで、1 文字の誤りでサービスが起動しなくなることがあります。そこで編集の前に、同じ内容の写しを .bak や日付入りの名前で残すのが現場の習慣です。なお、設定を読み込むディレクトリの中に写しを置くと、その写しまで読み込まれてしまう場合があるので、別の場所に置くと安全です。
- **覚え方**: 「触る前にコピー」を合言葉にし、.bak は back up の bak だと覚えます。
- **まちがえやすい**: バックアップがあることと、元に戻せることは別です。どのファイルをどこへ戻すかを決めていないと、いざというときに使えません。
- **関連語**: [テキストエディタ](#g-linux-editor) ／ [fstab](#g-linux-fstab) ／ [隠しファイル](#g-linux-dotfile)
- **確かめかた**: `ls -l /etc | grep bak` で残っている写しを探し、`diff 設定ファイル 写し` で違いを確認できます。
