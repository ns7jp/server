# 混同しやすい言葉の対比表

意味を取り違えたまま覚えると、現場の会話が少しずつずれていきます。似ている言葉は 2 つ 1 組で覚えると、あとから混ざりません。

## とくに間違えると事故になる 5 組

**1. 起動（start）と自動起動（enable）**

今すぐ動かす操作と、次に OS が起動したときも動かす設定は別物です。start だけで作業を終えると、サーバーを再起動した瞬間にサービスが上がってきません。設定できているかは `systemctl is-enabled サービス名` で確認できます。

**2. 再起動（restart）と再読み込み（reload）**

restart はいったん止めるため、その間の通信は失敗します。「設定を反映するだけ」のつもりで選ぶと、利用者から見れば短い障害になります。reload に対応しているかは `systemctl show -p CanReload サービス名` で確認できます。

**3. 冗長化とバックアップ**

冗長化は機器が壊れても止めない仕組みで、過去に戻す仕組みではありません。2 台に同じ内容を書き続ける構成では、誤って消したデータも両方から消えます。「二重化しているから安心」と思い込むと、削除事故のときに戻す先がありません。

**4. スナップショットとバックアップ**

スナップショットは同じ装置の中に残す使い方が多く、装置ごと壊れると一緒に失われます。別の場所に写しがあって、はじめてバックアップと呼べます。取れているかだけでなく、戻せるかを定期的に試すところまでが備えです。

**5. 秘密鍵と公開鍵**

相手に渡してよいのは公開鍵だけで、秘密鍵は自分の手元から出しません。名前が似ているため、接続がうまくいかないときに秘密鍵を送ってしまう事故が起きます。渡した時点で鍵を作り直すことになり、関係する設定をすべて入れ替える手間が生じます。
