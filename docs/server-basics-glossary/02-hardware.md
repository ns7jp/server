# 2. サーバーのハードウェア

[用語集の入口](README.md) / [さくいん](index.md) / [前: サーバーとクライアント](01-server-client.md) / [次: OS とプロセスの基礎](03-os-process.md)

サーバーの中身は、身構えなくても大丈夫です。エアコンや冷蔵庫の仕様表を読むのと同じ感覚で、部品の名前と役割を一つずつ結び付けていきましょう。

> **この章で最初に押さえる 3 語**: CPU ／ メモリ（RAM） ／ ストレージ

<a id="g-hw-motherboard"></a>
## マザーボード

- **一言**: CPU やメモリを差し込み、すべての部品をつなぐ土台の基板です。
- **たとえ**: 家の中を走る配線と分電盤のようなものです。電気も信号も、いったんここを通ってから各部屋（各部品）へ届きます。
- **くわしく**: CPU、メモリ、ストレージ、拡張カードは、すべてこの基板の差し込み口につながります。どの部品をいくつ載せられるかは、基板の設計で決まります。サーバー用は、メモリのスロット（差し込み口）や拡張カードの本数が多いのが特徴です。
- **覚え方**: 母（マザー）の板の上に、子ども（各部品）が乗っていると覚えます。
- **まちがえやすい**: 同じ名前の CPU でも、ソケット（差し込み口）の形と世代が合わなければ載りません。「新しいから速い」より先に、「合うかどうか」を確かめます。
- **関連語**: [CPU](#g-hw-cpu) ／ [メモリ（RAM）](#g-hw-memory) ／ [ファームウェア](#g-hw-firmware)
- **確かめかた**: `sudo dmidecode -t baseboard` で製造元と型番を確認できます。

<a id="g-hw-cpu"></a>
## CPU（シー・ピー・ユー）

- **一言**: 計算と判断を担当する、サーバーの頭脳にあたる部品です。
- **たとえ**: レストランの厨房に立つ料理人です。注文（処理の依頼）が届くと、材料（データ）を手早く調理して皿に載せます。
- **くわしく**: CPU は Central Processing Unit の略で、プログラムの命令を 1 つずつ読んで実行します。処理の速さは、このあとに出てくるコアの数とクロック周波数の組み合わせで決まります。CPU が忙しすぎると、他の部品に余裕があっても全体が遅くなります。この状態を「CPU がボトルネック（一番細い部分）になっている」と言います。
- **覚え方**: Central Processing Unit の頭文字で、厨房の中央に立つ料理人と覚えます。
- **まちがえやすい**: 使用率が 100% でも故障とは限らず、全力で働いているだけのこともあります。逆に使用率が低いのに、メモリ不足やディスクの遅さで全体が遅いこともあります。
- **関連語**: [コアとスレッド](#g-hw-core-thread) ／ [クロック周波数](#g-hw-clock) ／ [メモリ（RAM）](#g-hw-memory)
- **確かめかた**: `lscpu` でモデル名とコア数、`uptime` で直近の負荷（ロードアベレージ）を確認します。

<a id="g-hw-core-thread"></a>
## コアとスレッド（コア・スレッド）

- **一言**: コアは計算する頭数、スレッドは OS から見た窓口の数です。
- **たとえ**: 厨房に立つ料理人の人数がコアで、1 人が同時に受け持てる注文票の枚数がスレッドです。
- **くわしく**: 1 つの CPU には複数のコアが入っていて、コアの数だけ本当に同時に計算できます。ハイパースレッディングなどの技術は、1 コアを 2 スレッドに見せかけ、待ち時間を有効に使う工夫です。OS は「4 コア 8 スレッド」の CPU を 8 個の処理装置として扱いますが、性能が 2 倍になるわけではありません。
- **覚え方**: コアは料理人の人数、スレッドはその人が持つ手の数と覚えます。
- **まちがえやすい**: `nproc` が返す数はスレッド数（論理 CPU 数）で、物理コア数とは限りません。コア数でライセンス料が決まるソフトでは、特に取り違えに注意します。
- **関連語**: [CPU](#g-hw-cpu) ／ [クロック周波数](#g-hw-clock)
- **確かめかた**: `lscpu` の Core(s) per socket と Thread(s) per core、`nproc` で論理 CPU 数を確認します。

<a id="g-hw-clock"></a>
## クロック周波数（クロックシュウハスウ）

- **一言**: CPU が 1 秒間に刻む拍の回数で、GHz で表す速さの目安です。
- **たとえ**: 料理人が包丁を動かすテンポです。テンポが速いほど、1 つの作業が早く片づきます。
- **くわしく**: 3.0 GHz なら、1 秒間に 30 億回の拍を刻みます。同じ設計の CPU どうしなら、この数字が大きいほど 1 つの処理は速く終わります。世代が違うと 1 拍でこなせる仕事量そのものが違うため、数字だけでは比べられません。サーバー用 CPU の多くは、負荷や温度に応じて周波数を自動で上げ下げします。
- **覚え方**: 速さは「テンポ（周波数）× 人数（コア数）」で決まる、と覚えます。
- **まちがえやすい**: `lscpu` に出る MHz は今この瞬間の値で、負荷や省電力の設定によって刻々と変わります。カタログの最大値と違っていても、故障ではありません。
- **関連語**: [CPU](#g-hw-cpu) ／ [コアとスレッド](#g-hw-core-thread)
- **確かめかた**: `lscpu | grep -i mhz` や `grep MHz /proc/cpuinfo` で、現在の動作周波数を見られます。

<a id="g-hw-memory"></a>
## メモリ（RAM）（メモリ・ラム）

- **一言**: 作業中のデータを一時的に置く、電源を切ると消える置き場です。
- **たとえ**: 料理人が使う調理台です。広いほど材料を並べて同時進行できますが、閉店（電源オフ）で全部片づけられ、何も残りません。
- **くわしく**: RAM は Random Access Memory の略です。実行中のプログラムとそのデータは、まずメモリに読み込まれ、そこから CPU が処理します。容量が大きいほど、同時に扱える仕事が増えます。足りなくなるとスワップが起きたり、Linux では OOM Killer（メモリ不足のときにプロセスを強制終了する仕組み）が働いたりします。
- **覚え方**: メモリは調理台の広さ、ストレージは冷蔵庫の大きさ、と対にして覚えます。
- **まちがえやすい**: Linux は空きメモリが少なく見えますが、その多くはキャッシュ（読み込んだデータの一時保管）で、必要になれば手放されます。`free` の表示は、free ではなく available を見ます。
- **関連語**: [スワップ](#g-hw-swap) ／ [ストレージ](#g-hw-storage) ／ [ECC メモリ](#g-hw-ecc)
- **確かめかた**: `free -h` で使用量と available、`sudo dmidecode -t memory` で搭載スロットと容量を確認します。

<a id="g-hw-ecc"></a>
## ECC メモリ（イー・シー・シー・メモリ）

- **一言**: データの化けを自動で見つけて直す、サーバー向けのメモリです。
- **たとえ**: 会計のたびに検算までしてくれるレジです。打ち間違いをその場で見つけ、黙って直してくれます。
- **くわしく**: ECC は Error Correcting Code（誤り訂正符号）の略です。ノイズなどでビットが 1 つ反転しても、その場で訂正して処理を続けます。訂正しきれない誤りは記録に残るので、故障した部品を早く特定できます。使うにはマザーボードと CPU の対応が必要で、対応できるかは環境によって異なります。
- **覚え方**: ECC は「エラーをチェックしてコレクト（訂正）する」と読み替えます。
- **まちがえやすい**: ECC でも壊れないわけではありません。訂正できたエラーが増え続けているなら、それは交換を考える合図です。
- **関連語**: [メモリ（RAM）](#g-hw-memory) ／ [サーバー機と PC の違い](#g-hw-server-vs-pc) ／ [BMC（iLO / iDRAC / IPMI）](#g-hw-bmc)
- **確かめかた**: `sudo dmidecode -t memory` の Error Correction Type、`sudo edac-util -v`（導入していない環境もあります）で訂正エラーの件数を見ます。

<a id="g-hw-swap"></a>
## スワップ

- **一言**: メモリが足りないとき、中身の一部をストレージへ退避する仕組みです。
- **たとえ**: 調理台が手狭になり、当面使わない材料を床下収納にしまう動きです。また使うときは、取りに降りる手間がかかります。
- **くわしく**: Linux ではスワップ領域（専用の区画、またはスワップファイル）に、しばらく使わないメモリの内容を書き出します。おかげでメモリが足りなくても動き続けられますが、ストレージはメモリよりずっと遅い置き場です。出し入れが頻発すると全体が極端に遅くなります。これをスラッシングと呼び、メモリ増設を検討する合図になります。
- **覚え方**: swap は交換で、メモリの荷物を遅い倉庫と交換して置いてくる動きだと覚えます。
- **まちがえやすい**: スワップを使っていること自体は、すぐに異常とは限りません。問題なのは、使用量が増え続けて出し入れが止まらない状態です。
- **関連語**: [メモリ（RAM）](#g-hw-memory) ／ [ストレージ](#g-hw-storage)
- **確かめかた**: `swapon --show` で領域、`free -h` で使用量、`vmstat 1 5` の si ／ so 列で出し入れの発生を見ます。

<a id="g-hw-storage"></a>
## ストレージ

- **一言**: 電源を切っても消えない、データを保存しておく装置の総称です。
- **たとえ**: 厨房の冷蔵庫と食品庫です。閉店して電気を落としても中身は残り、翌朝そのまま使えます。
- **くわしく**: OS もアプリも設定ファイルもログも、すべてストレージの上に置かれます。速さは容量とは別の話で、このあとに出てくる HDD・SSD・NVMe で大きく変わります。サーバーでは容量に加えて、IOPS（1 秒あたりに処理できる読み書きの回数）と耐久性も選ぶ材料になります。空き容量が尽きると書き込みが失敗し、サービスが止まることもあるため、監視の定番項目です。
- **覚え方**: ストレージは store（しまう）で、消えずに残る置き場だと覚えます。
- **まちがえやすい**: 空き容量があっても、i ノード（ファイル 1 つずつに割り当てられる管理情報）が尽きると書き込めません。`df -h` と `df -i` の両方を見ます。
- **関連語**: [HDD](#g-hw-hdd) ／ [SSD](#g-hw-ssd) ／ [RAID（0/1/5/6/10）](#g-hw-raid)
- **確かめかた**: `lsblk` で接続されている装置の一覧、`df -h` で使用量を確認します。

<a id="g-hw-hdd"></a>
## HDD（エイチ・ディー・ディー）

- **一言**: 磁気の円盤を回して読み書きする、大容量で安価なストレージです。
- **たとえ**: レコードプレーヤーです。針（ヘッド）が目的の溝までたどり着くまで、こちらは待たされます。
- **くわしく**: HDD は Hard Disk Drive の略で、内部で円盤が回り、ヘッドが移動して目的の場所を読み書きします。物理的に動く部品があるため、あちこちに散らばった小さなデータの読み書きは苦手です。一方で容量あたりの価格は安く、ログの保管やバックアップの置き場に向きます。振動と衝撃に弱いので、ラックでの取り扱いは丁寧に行います。
- **覚え方**: 回る円盤と動く針でレコードプレーヤー、針が動くぶんだけ待たされると覚えます。
- **まちがえやすい**: 回転数（rpm）が高いからといって、どんな用途でも速いわけではありません。細かい読み書きが多い用途では、SSD との差がけた違いに開きます。
- **関連語**: [SSD](#g-hw-ssd) ／ [ストレージ](#g-hw-storage) ／ [RAID（0/1/5/6/10）](#g-hw-raid)
- **確かめかた**: `lsblk -d -o NAME,ROTA,SIZE,MODEL` の ROTA が 1 なら回転する装置です。`sudo smartctl -a /dev/sda` で健康状態も確認できます。

<a id="g-hw-ssd"></a>
## SSD（エス・エス・ディー）

- **一言**: 半導体に記録する、動く部品がない高速なストレージです。
- **たとえ**: 書庫の奥まで本を取りに行く代わりに、手元の電子書籍を目次から一発で開く感覚です。
- **くわしく**: SSD は Solid State Drive の略で、フラッシュメモリ（電源を切っても消えない半導体の記憶素子）にデータを保存します。ヘッドの移動がないので、散らばった小さなファイルの読み書きが HDD よりけた違いに速いです。ただし書き込める回数には上限があり、サーバー用は書き込み耐久（どれだけ書き込めるかの指標）を見て選びます。同じ SATA 接続でも、HDD と入れ替えるだけで体感が変わります。
- **覚え方**: Solid State は「動く部品がない」という意味で、動かないから速いと覚えます。
- **まちがえやすい**: SSD だから壊れない、ということはありません。予兆なく寿命が来ることもあるため、RAID もバックアップも必要です。
- **関連語**: [HDD](#g-hw-hdd) ／ [NVMe](#g-hw-nvme) ／ [ストレージ](#g-hw-storage)
- **確かめかた**: `lsblk -d -o NAME,ROTA,MODEL` の ROTA が 0 か、`sudo smartctl -a /dev/sda` で消耗度の項目を確認します。

<a id="g-hw-nvme"></a>
## NVMe（エヌ・ブイ・エム・イー）

- **一言**: SSD を PCIe で直結してつなぐ、記憶装置向けの通信規格です。
- **たとえ**: 片側 1 車線の一般道（SATA）から、高速道路（PCIe）へ乗り換えるようなものです。
- **くわしく**: NVMe は Non-Volatile Memory Express の略で、フラッシュメモリ用に設計された規格です。HDD 向けに作られた SATA と違い、CPU に近い PCIe（拡張カード用の高速な通り道）を直接使います。たくさんの命令を並べて同時に処理できるので、データベースなど読み書きの多い用途で効果が出ます。OS から見えるデバイス名も `/dev/sda` ではなく `/dev/nvme0n1` のような形になります。
- **覚え方**: NVMe は不揮発メモリ専用の Express（特急）レーンだと覚えます。
- **まちがえやすい**: NVMe は「SSD の一種」ではなく「つなぎ方の規格」です。中身は SSD で、SATA 接続の SSD も普通にあります。
- **関連語**: [SSD](#g-hw-ssd) ／ [ストレージ](#g-hw-storage)
- **確かめかた**: `lsblk` に nvme で始まる名前があるか、`ls /dev/nvme*`、`sudo nvme list`（導入していない環境もあります）で確認します。

<a id="g-hw-raid"></a>
## RAID（0/1/5/6/10）（レイド）

- **一言**: 複数のディスクを束ねて、速さや壊れにくさを高める仕組みです。
- **たとえ**: 大事な書類を 2 か所の金庫に同じ内容で入れるか（RAID 1）、手分けして早く運ぶか（RAID 0）の選び方です。
- **くわしく**: RAID は Redundant Array of Independent Disks の略です。RAID 0 は分散して書くので速い代わりに、1 本壊れると全滅します。RAID 1 は同じ内容を 2 本に書く鏡（ミラー）で、RAID 10 は鏡の組を並べて速さも足した形です。RAID 5 はパリティ（壊れた分を復元する符号）で 1 本まで、RAID 6 は 2 本までの故障に耐えます。
- **覚え方**: 0 は守りゼロ、1 は鏡、5 は 1 本まで、6 は 2 本まで、10 は 1 と 0 の合わせ技と覚えます。
- **まちがえやすい**: RAID はバックアップの代わりになりません。誤って消したファイルは、すべてのディスクから同時に消えます。
- **関連語**: [ホットスペア](#g-hw-hot-spare) ／ [ホットスワップ](#g-hw-hot-swap) ／ [ストレージ](#g-hw-storage)
- **確かめかた**: ソフトウェア RAID は `cat /proc/mdstat`、ハードウェア RAID はカード付属の管理ツール（製品によって異なります）で状態を見ます。

<a id="g-hw-hot-swap"></a>
## ホットスワップ

- **一言**: 電源を入れたまま部品を抜き差しできる仕組みのことです。
- **たとえ**: パソコンの電源を切らずに USB メモリを抜き差しするのと同じ感覚です。サーバーではディスクや電源、ファンでも同じことができます。
- **くわしく**: 対応した機器では、前面のトレイごとディスクを引き抜き、新しいものを差し込めます。サービスを止めずに故障部品を交換できるのが利点で、ディスクの場合は RAID と組み合わせて効果を発揮します。対応しているかは機種と部位で決まり、非対応の機器で抜けば故障や停止につながります。
- **覚え方**: hot（電源が入ったまま）と swap（交換）で、「熱いまま交換」と覚えます。
- **まちがえやすい**: 対応機器でも、抜く前に OS 側や RAID カード側で切り離す操作が必要な場合があります。トレイのランプの色と管理画面の表示を、必ず両方確認します。
- **関連語**: [ホットスペア](#g-hw-hot-spare) ／ [RAID（0/1/5/6/10）](#g-hw-raid) ／ [電源ユニット（PSU）と冗長電源](#g-hw-psu)
- **確かめかた**: 機器のマニュアルで対応部位を確認し、`lsblk` や `cat /proc/mdstat` で対象ディスクの位置と状態を確かめます。

<a id="g-hw-hot-spare"></a>
## ホットスペア

- **一言**: 故障に備えて待機させておく、RAID の予備ディスクです。
- **たとえ**: 野球のベンチに座る交代要員です。誰かが倒れた瞬間、指示を待たずにグラウンドへ出ます。
- **くわしく**: 普段は使われず、電源が入った状態で待機しているディスクです。構成メンバーが 1 本壊れると自動でリビルド（データの再構築）が始まり、壊れても耐えられる状態へ早く戻せます。人が現地に着くまでの時間を稼げるのが利点です。どの構成の予備にするかは、RAID カードや OS 側の設定で指定します。
- **覚え方**: スワップは「交換する手」、スペアは「控えの一枚」と区別して覚えます。
- **まちがえやすい**: 予備が働いた時点で、その予備はもういません。故障したディスクの物理交換は、結局そのあとに必要です。
- **関連語**: [RAID（0/1/5/6/10）](#g-hw-raid) ／ [ホットスワップ](#g-hw-hot-swap)
- **確かめかた**: `cat /proc/mdstat` の (S) 表示や、RAID カードの管理ツールでスペアの登録状況を確認します。

<a id="g-hw-nic"></a>
## NIC（ネットワークインターフェースカード）（エヌ・アイ・シー）

- **一言**: サーバーをネットワークにつなぐ部品で、LAN ケーブルの差し口です。
- **たとえ**: 建物の郵便受けです。口ごとに表札（MAC アドレス）が付いていて、届いた郵便物を中へ取り込みます。
- **くわしく**: NIC は Network Interface Card の略です。口ごとに MAC アドレス（口に割り当てられた固有の識別番号）を持ち、OS からは `eth0` や `ens192` のような名前で見えます。サーバーは NIC を複数持つことが多く、業務用・管理用・バックアップ用と役割を分けて使います。速度は 1 Gbps や 10 Gbps などがあり、機器によって異なります。
- **覚え方**: NIC は Network Interface Card の頭文字で、ネットの玄関口だと覚えます。
- **まちがえやすい**: リンクアップ（ケーブルが挿さってランプが光っている状態）と、通信できることは別です。IP アドレスや経路の設定が合っていなければ、光っていても通りません。
- **関連語**: [チーミング（ボンディング）](#g-hw-teaming) ／ [BMC（iLO / iDRAC / IPMI）](#g-hw-bmc)
- **確かめかた**: `ip -br link` で口の一覧と状態、`ip -br addr` で IP アドレス、`sudo ethtool eth0` で速度とリンク状況を見ます。

<a id="g-hw-teaming"></a>
## チーミング（ボンディング）（チーミング・ボンディング）

- **一言**: 複数の NIC を束ねて 1 本に見せ、冗長化や高速化をする技術です。
- **たとえ**: 引っ越しでトラックを 2 台出すようなものです。1 台が故障しても荷物は届き、2 台とも使えば早く運べます。
- **くわしく**: Windows ではチーミング、Linux ではボンディング（bonding）と呼ぶのが一般的です。束ね方の種類（モード）があり、片方を待機させる冗長重視の構成と、両方を同時に使う速度重視の構成があります。速度重視のモードは、スイッチ側の設定（LACP という束ね方の取り決め）と合わせる必要があります。OS からは `bond0` や `team0` という 1 つの口として見えます。
- **覚え方**: チーム（team）を組ませて、2 本を 1 本のように見せると覚えます。
- **まちがえやすい**: 束ねれば必ず 2 倍速、というわけではありません。1 つの通信は 1 本の物理回線しか使わないことが多く、合計の帯域が増えるだけの場合があります。
- **関連語**: [NIC（ネットワークインターフェースカード）](#g-hw-nic) ／ [電源ユニット（PSU）と冗長電源](#g-hw-psu)
- **確かめかた**: `cat /proc/net/bonding/bond0` で構成と現在使っている口、`ip -br link` で束ねた口の状態を確認します。

<a id="g-hw-psu"></a>
## 電源ユニット（PSU）と冗長電源（デンゲンユニット・ジョウチョウデンゲン）

- **一言**: コンセントの電気を機器用に変える箱と、それを 2 台以上載せる構成です。
- **たとえ**: スマホの充電器と同じ役割の部品です。冗長電源は、その充電器を 2 本挿しておき、1 本抜けても切れないようにした形です。
- **くわしく**: PSU は Power Supply Unit の略で、コンセントの交流を機器内部で使う直流に変えます。冗長電源は PSU を 2 台以上積み、1 台が壊れても残りで動き続ける構成です。対応した機種では、動かしたまま 1 台ずつ交換できます。効果を出すには、2 本の電源ケーブルを別々の電源系統に挿すことが大切です。
- **覚え方**: 冗長はむだではなく命綱で、2 本挿しは片方が抜けても止めないための保険だと覚えます。
- **まちがえやすい**: 2 台積んでいても、同じテーブルタップに挿していれば意味が薄れます。その系統ごと落ちたら、両方まとめて止まります。
- **関連語**: [UPS（無停電電源装置）](#g-hw-ups) ／ [ホットスワップ](#g-hw-hot-swap) ／ [BMC（iLO / iDRAC / IPMI）](#g-hw-bmc)
- **確かめかた**: `sudo ipmitool sdr list` や BMC の画面で PSU の状態、本体背面のランプの色を確認します。

<a id="g-hw-bmc"></a>
## BMC（iLO / iDRAC / IPMI）（ビー・エム・シー）

- **一言**: 本体とは別に動き、遠隔で電源操作や監視ができる管理用の小型コンピューターです。
- **たとえ**: 留守宅に置いたカメラ付きのリモコンです。コンセントさえ生きていれば、家の中が真っ暗でも外から様子を見て電気を入れられます。
- **くわしく**: BMC は Baseboard Management Controller の略で、マザーボード上で本体とは独立して動きます。専用の LAN ポートに IP アドレスを割り当てると、ブラウザや `ipmitool` から温度・ファン・電源の状態を見て操作できます。HPE では iLO（アイ・エル・オー）、Dell では iDRAC（アイドラック）と製品名が違います。IPMI（アイ・ピー・エム・アイ）はこれらに共通する古くからの規格で、現地へ行かずに復旧できる遠隔運用の生命線です。
- **覚え方**: 本体が寝ていても起きている、もう 1 台の小さなサーバーだと覚えます。
- **まちがえやすい**: BMC の IP アドレスは OS の IP アドレスとは別物で、OS を入れ替えても BMC の設定は残ります。ただし電源ケーブルが抜けていれば BMC も動かないので、そこからは遠隔で戻せません。
- **関連語**: [KVM スイッチ](#g-hw-kvm-switch) ／ [NIC（ネットワークインターフェースカード）](#g-hw-nic) ／ [ファームウェア](#g-hw-firmware)
- **確かめかた**: `sudo ipmitool lan print 1` で BMC の IP アドレス、`sudo ipmitool sensor list` で温度やファンの値を見ます。IPMI を無効にしている機種では、BMC の Web 画面から確認します。

<a id="g-hw-kvm-switch"></a>
## KVM スイッチ（ケー・ブイ・エム・スイッチ）

- **一言**: 1 組のキーボードと画面とマウスを複数台で切り替える装置です。
- **たとえ**: テレビの入力切替です。1 台の画面で、ゲーム機と録画機を切り替えて見るのと同じ仕組みです。
- **くわしく**: KVM は Keyboard・Video（画面）・Mouse の頭文字です。ラックにサーバーが何台も並ぶ現場で、操作用の機材を 1 組だけ用意し、ボタンで相手を切り替えて使います。ネットワーク越しに使える IP-KVM もあり、遠隔から画面を操作できます。BMC の遠隔画面が広まった今も、BMC のない機器や管理ネットワークが不調なときの備えとして残っています。
- **覚え方**: K・V・M はキーボード、ビデオ（画面）、マウスの 3 点セットだと覚えます。
- **まちがえやすい**: 仮想化の KVM（Kernel-based Virtual Machine）とは、名前が同じだけの別物です。求人票や手順書では、文脈で読み分けます。
- **関連語**: [BMC（iLO / iDRAC / IPMI）](#g-hw-bmc) ／ [ラックマウント型・タワー型・ブレード](#g-hw-form-factor)
- **確かめかた**: ラック前面のコンソール（引き出し式の画面）と切替ボタン、または IP-KVM の管理画面で確認します。

<a id="g-hw-ups"></a>
## UPS（無停電電源装置）（ユー・ピー・エス・ムテイデンデンゲンソウチ）

- **一言**: 停電しても電池でしばらく電気を送り続ける装置です。
- **たとえ**: ノートパソコンのバッテリーを、サーバーに外付けしたようなものです。コンセントが抜けても、しばらくは動き続けます。
- **くわしく**: UPS は Uninterruptible Power Supply の略です。停電を検知すると電池に切り替え、その間に安全に電源を落とす（正常終了させる）時間を稼ぎます。多くは USB や LAN でサーバーとつながり、停電時の自動シャットダウンを指示できます。電池は消耗品なので、定期的な交換と自己診断の確認が必要です。
- **覚え方**: Un（無）と interruptible（中断される）で、「中断されない電源」と読み解きます。
- **まちがえやすい**: 停電中もずっと動かし続けるための装置ではありません。持続時間は容量と負荷で決まり、環境によって異なります。
- **関連語**: [電源ユニット（PSU）と冗長電源](#g-hw-psu) ／ [ラックマウント型・タワー型・ブレード](#g-hw-form-factor)
- **確かめかた**: NUT という UPS 管理ソフトを使う環境なら、`upsc -l` で登録名、`upsc ups@localhost` のように指定して電池残量を見ます。付属の管理ソフトでも同じ内容を確認できます。

<a id="g-hw-form-factor"></a>
## ラックマウント型・タワー型・ブレード（ラックマウントガタ・タワーガタ・ブレード）

- **一言**: サーバー本体の形の分類で、置き方と収容効率が変わります。
- **たとえ**: 棚に寝かせて並べる本（ラック）、床に立てる本棚そのもの（タワー）、書類ケースに差し込むファイル（ブレード）の違いです。
- **くわしく**: ラックマウント型は 19 インチラックにレールで固定する薄い箱型で、データセンターの標準です。タワー型は机の横に置ける縦置きで、事務所や小規模拠点に向きます。ブレードは板状の本体を専用のシャーシ（収める筐体）へ差し込み、電源やネットワークを共有して高密度に集約する方式です。設置場所と冷却、電源の条件で選びます。
- **覚え方**: ラックは棚に差す、タワーは塔のように立てる、ブレードは刃のように薄い板と覚えます。
- **まちがえやすい**: タワー型をそのままラックに載せることはできません。機種によっては専用のラック搭載キットが用意されています。
- **関連語**: [ラックユニット（U）](#g-hw-rack-unit) ／ [KVM スイッチ](#g-hw-kvm-switch) ／ [UPS（無停電電源装置）](#g-hw-ups)
- **確かめかた**: `sudo dmidecode -t chassis` の Type や、機器の型番と仕様書から形状を確認します。

<a id="g-hw-rack-unit"></a>
## ラックユニット（U）（ラックユニット・ユー）

- **一言**: ラックの高さを数える単位で、1U は約 4.4cm 分の厚みです。
- **たとえ**: 引き出しの段数と同じ数え方です。「この棚は 42 段ぶん、この機械は 2 段ぶん」と数えます。
- **くわしく**: 19 インチラックの高さは U（ユニット）で表し、1U は 1.75 インチ（約 44.45mm）です。サーバーは 1U・2U・4U といった厚みで作られ、ラックの段数（例: 42U）から載せられる台数を見積もります。薄いほど台数を詰め込めますが、冷却とディスク搭載数の制約は厳しくなります。設置計画では、段数だけでなく重量と電源容量も合わせて確認します。
- **覚え方**: U は Unit（段）の頭文字で、引き出しの段数と同じ数え方だと覚えます。
- **まちがえやすい**: 段数が空いていても、奥行きや重量、電源容量が足りずに載せられないことがあります。U は大きさの単位で、性能とは関係ありません。
- **関連語**: [ラックマウント型・タワー型・ブレード](#g-hw-form-factor)
- **確かめかた**: 機器の仕様書にある高さ表記（1U/2U）と、ラックの空き段数を実際に数えて確認します。

<a id="g-hw-bit-byte"></a>
## bit と byte（ビット・バイト）

- **一言**: bit は 0 か 1 の最小単位で、8 bit を 1 byte と呼びます。
- **たとえ**: bit は電球 1 個の点灯と消灯、byte はその電球を 8 個並べて表す 1 文字分です。
- **くわしく**: 通信速度は bps（bit 毎秒）、ファイルの容量は B（byte）で表すのが慣習です。1 byte は 8 bit なので、100 Mbps の回線で受け取れるのは理論上でも毎秒 12.5 MB 程度です。表記は小文字 b が bit、大文字 B が byte です。ここを混同すると、見積もりが 8 倍ずれます。
- **覚え方**: 小文字 b は小さい bit、大文字 B は大きい byte と、文字の大きさで覚えます。
- **まちがえやすい**: 「1 Gbps の回線だから 1 秒で 1 GB 送れる」は誤りです。8 分の 1 が上限の目安で、実際にはさらに下がります。
- **関連語**: [K・M・G・T（単位の接頭語）](#g-hw-si-prefix) ／ [NIC（ネットワークインターフェースカード）](#g-hw-nic)
- **確かめかた**: `sudo ethtool eth0` の Speed は bit 毎秒、`df -h` の表示は byte です。単位の文字を見比べます。

<a id="g-hw-si-prefix"></a>
## K・M・G・T（単位の接頭語）（ケー・エム・ジー・ティー）

- **一言**: キロ・メガ・ギガ・テラと 1000 倍ずつ大きくなる接頭語です。
- **たとえ**: 1 円、1000 円、100 万円と桁が上がっていく感覚です。呼び名が変わるだけで、数え方の考え方は同じです。
- **くわしく**: 10 進では K が 1000 倍、M が 100 万倍、G が 10 億倍、T が 1 兆倍です。コンピューターは 2 の累乗で数えることも多く、1024 倍ずつの場合は KiB・MiB・GiB（キビ・メビ・ギビ）と書き分けます。ストレージや通信速度は 1000 進で表記されることが多く、OS が 1024 進で表示すると「買ったより少ない」ように見えます。この差は故障でも不良品でもありません。
- **覚え方**: キロ・メガ・ギガ・テラは 3 桁ずつ増え、i が付いたら 1024 進だと覚えます。
- **まちがえやすい**: 1TB のディスクが OS 上で約 931GiB と表示されるのは、数え方の違いによるものです。1024 進の値を GB と表示するソフトもあり、単位の文字だけでは判断できません。
- **関連語**: [bit と byte](#g-hw-bit-byte) ／ [ストレージ](#g-hw-storage)
- **確かめかた**: `df -h`（1024 進）と `df -H`（1000 進）を見比べると、同じ領域で数字が変わることが分かります。

<a id="g-hw-bios-uefi"></a>
## BIOS と UEFI（バイオス・ユー・イー・エフ・アイ）

- **一言**: 電源投入の直後に働き、OS を起動させる土台のプログラムです。
- **たとえ**: 開店前の店長です。電気と設備をひと通り点検し、鍵を開けてからスタッフ（OS）を中へ呼び入れます。
- **くわしく**: BIOS（Basic Input/Output System）は古くからある方式で、UEFI はその後継にあたります。どちらも電源投入後にハードウェアを初期化し、起動用ディスクを探して OS の読み込みへ引き継ぎます。UEFI は GPT という新しい区画の方式と組み合わせ、2TB を超えるディスクからの起動にも対応します。起動順序や仮想化支援（仮想マシンを速く動かす機能）の設定も、この画面で行います。
- **覚え方**: BIOS は先代、UEFI は新型で、どちらも OS を起こす前の準備係だと覚えます。
- **まちがえやすい**: この設定は OS の中ではなく、機器側に保存されます。OS を入れ直しても、起動モード（レガシー ／ UEFI）が合っていなければ立ち上がりません。
- **関連語**: [ファームウェア](#g-hw-firmware) ／ [BMC（iLO / iDRAC / IPMI）](#g-hw-bmc)
- **確かめかた**: `ls /sys/firmware/efi` が存在すれば UEFI で起動しています。`sudo dmidecode -t bios` でバージョンを確認します。

<a id="g-hw-firmware"></a>
## ファームウェア

- **一言**: 機器そのものに組み込まれ、部品を動かす専用のプログラムです。
- **たとえ**: 家電に最初から入っている頭脳です。炊飯器が「炊く」手順をあらかじめ覚えているのと同じです。
- **くわしく**: BIOS/UEFI、RAID カード、NIC、ディスク、BMC など、部品ごとに固有のファームウェアが載っています。不具合の修正や新しい部品への対応、脆弱性（攻撃に使われる弱点）への対策として更新版が提供されます。更新には再起動や短時間の停止を伴うことが多く、事前の計画と手順確認が欠かせません。部品どうしの推奨される組み合わせが決まっていることもあるため、メーカーの対応表に従います。
- **覚え方**: ソフトとハードの中間にあるから firm（かたい）ウェア、と覚えます。
- **まちがえやすい**: OS のアップデートをしても、ファームウェアは基本的に上がりません。別の作業として計画し、管理します。
- **関連語**: [BIOS と UEFI](#g-hw-bios-uefi) ／ [BMC（iLO / iDRAC / IPMI）](#g-hw-bmc) ／ [マザーボード](#g-hw-motherboard)
- **確かめかた**: `sudo dmidecode -t bios` や `sudo fwupdmgr get-devices`（導入していない環境もあります）で、現在のバージョンを一覧できます。

<a id="g-hw-server-vs-pc"></a>
## サーバー機と PC の違い（サーバーキトピーシーノチガイ）

- **一言**: 同じ計算機でも、24 時間動かし続ける前提かどうかが違います。
- **たとえ**: 自家用車と路線バスの違いです。走る仕組みは同じでも、毎日走り続ける前提のバスは、点検も部品も交換のしやすさも別物です。
- **くわしく**: サーバー機は連続運転を前提に、ECC メモリ、冗長電源、ホットスワップ対応のディスク、BMC による遠隔管理などを備えます。ラックに収まる形状で、前面から吸って背面へ抜ける空気の流れを想定して設計されています。そのぶん静かさは重視されず、多くは事務所に置ける音ではありません。PC でもサービスは動きますが、壊れたときに止まる時間と復旧の手間が大きく変わります。
- **覚え方**: サーバーは速さより「止まらない工夫」にお金がかかっている、と覚えます。
- **まちがえやすい**: 高性能な PC が、そのままサーバーになるわけではありません。違いは性能の数字ではなく、冗長性（壊れても止まらない備え）・遠隔管理・保守のしやすさにあります。
- **関連語**: [ECC メモリ](#g-hw-ecc) ／ [BMC（iLO / iDRAC / IPMI）](#g-hw-bmc) ／ [ラックマウント型・タワー型・ブレード](#g-hw-form-factor)
- **確かめかた**: `sudo dmidecode -t system` で製造元と型番、`uptime` で連続稼働時間を確認します。
