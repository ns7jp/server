# 3. OS とプロセスの基礎

[用語集の入口](README.md) / [さくいん](index.md) / [前: サーバーのハードウェア](02-hardware.md) / [次: Linux のファイル・ユーザー・パッケージ](04-linux.md)

サーバーの中では、OS という土台の上でたくさんのプログラムが同時に動いています。この章では「いま何が動いているのか」を自分の言葉で説明できるようになることを目指します。

> **この章で最初に押さえる 3 語**: OS ／ プロセス ／ サービス

<a id="g-os-os"></a>
## OS（オー・エス）

- **一言**: ハードウェアとアプリの間に立ち、CPU やメモリの割り当てを仕切る基本ソフトです。
- **たとえ**: 貸し会議室ビルの管理人です。部屋（メモリ）や電源（CPU の時間）を、順番を決めて貸し出し、終われば回収します。
- **くわしく**: OS はオペレーティングシステムの略で、日本語では基本ソフトと呼びます。アプリは機械を直接触らず、「ファイルを読みたい」「通信したい」と OS 越しに頼みます。おかげで機種が違っても同じアプリが動き、1 台の機械を複数のプログラムで分け合えます。
- **覚え方**: Operating は「運行」、System は「仕組み」。サーバーの運行管理室だと覚えます。
- **まちがえやすい**: 「OS を再起動する」と「アプリを再起動する」は別の作業です。1 つのアプリの不調で OS ごと再起動すると、同じ機械の無関係なサービスまで巻き添えで止まります。
- **関連語**: [カーネル](#g-os-kernel)、[ディストリビューション](#g-os-distribution)、[プロセス](#g-os-process)
- **確かめかた**: `cat /etc/os-release` で OS の名前と版が出ます。Windows なら `winver` です。

<a id="g-os-kernel"></a>
## カーネル

- **一言**: OS の中心にあり、CPU やメモリ、機器への出入りを直接さばく部分です。
- **たとえ**: レストランの厨房です。客（アプリ）は厨房に入れず、注文票を出して料理を受け取ります。
- **くわしく**: カーネルはメモリの割り当て、プロセスの切り替え、ディスクやネットワーク機器の操作を受け持ちます。アプリはシステムコール（カーネルへの決まった頼み方）という窓口を通してのみ、これらを頼めます。この仕切りがあるので、1 つのアプリが暴走しても機械全体が巻き込まれにくくなります。
- **覚え方**: kernel は木の実の「核」。殻（シェル）の内側にある芯だと覚えます。
- **まちがえやすい**: 「Linux は OS 全体の名前」と思われがちですが、Linux はカーネルの名前です。周りの道具一式まで含めた配布物がディストリビューションです。
- **関連語**: [OS](#g-os-os)、[ディストリビューション](#g-os-distribution)、[シェル](#g-os-shell)
- **確かめかた**: `uname -r` でカーネルの版が出ます。表示される数字は環境によって異なります。

<a id="g-os-distribution"></a>
## ディストリビューション

- **一言**: Linux カーネルに道具一式を詰め合わせて配る、ひとそろいの配布物です。
- **たとえ**: 家具家電つきの賃貸物件です。柱と壁（カーネル）だけでは暮らせないので、鍋や食器（各種コマンド）まで最初からそろえてあります。
- **くわしく**: Linux カーネル本体に、シェル、各種コマンド、初期設定をまとめたものです。ソフトの出し入れを台帳で管理する道具（パッケージ管理の仕組み）も最初から入っています。配布元が組み合わせの動作確認と更新の提供を引き受けるため、利用者は完成した状態から使い始められます。Ubuntu、Debian、RHEL、AlmaLinux などが代表例で、無償のものも有償のものもあります。
- **覚え方**: distribute は「配る」。中身のカーネルは同じで、配り方の違いだと覚えます。
- **まちがえやすい**: 見た目が違うだけと思われがちですが、パッケージ管理の道具も設定ファイルの置き場所も異なります。手順書は必ず対象のディストリビューション向けを使います。
- **関連語**: [カーネル](#g-os-kernel)、[Ubuntu と Red Hat 系](#g-os-ubuntu-redhat)、[パッケージマネージャ](#g-os-package-manager)
- **確かめかた**: `cat /etc/os-release` の `ID` と `VERSION_ID` の行を見ます。

<a id="g-os-ubuntu-redhat"></a>
## Ubuntu と Red Hat 系（ウブントゥ ／ レッドハットケイ）

- **一言**: Linux の代表的な二系統で、パッケージ管理の道具と作法が違います。
- **たとえ**: 右ハンドル車と左ハンドル車です。走る仕組みは同じでも、ウインカーの位置が違って最初は戸惑います。
- **くわしく**: Ubuntu は Debian 系で、ソフトの導入に `apt` という道具を使います。Red Hat 系には有償の RHEL と、それに合わせた AlmaLinux や Rocky Linux があります。こちらは `dnf`（古い版では `yum`）を使います。設定ファイルの場所やサービスの名前も系統ごとに違うので、作業の前にどちらかを確かめます。
- **覚え方**: 荷物の形で覚えます。Debian 系のソフトは `.deb`、Red Hat 系は `.rpm`（Red Hat Package Manager の頭文字）です。
- **まちがえやすい**: AlmaLinux や Rocky Linux は、RHEL との互換を目指して作られた別の配布物です。RHEL 向けの手順がそのまま通ることは多いものの、同じものではありません。
- **関連語**: [ディストリビューション](#g-os-distribution)、[パッケージマネージャ](#g-os-package-manager)、[LTS](#g-os-lts)
- **確かめかた**: `cat /etc/os-release` で名前を確認します。`command -v apt dnf` で、どちらの道具が入っているかも分かります。

<a id="g-os-lts"></a>
## LTS（エル・ティー・エス）

- **一言**: 修正の提供が長く続く、長期サポート版のことです。
- **たとえ**: 家電の長期保証です。新機能は増えませんが、壊れたときの修理窓口が長く開いています。
- **くわしく**: Long Term Support の略で、機能追加より安定と修正の継続を優先した版です。サーバーは何年も動かし続けるため、更新が途切れない LTS を選ぶのが基本になります。サポートの期間や呼び方は配布元と版によって異なるので、公式の情報で確認します。
- **覚え方**: L は Long、T は Term、S は Support。「長く面倒を見る版」です。
- **まちがえやすい**: LTS ならずっと安全と思いがちですが、期限は必ず来ます。期限を過ぎた版には修正が届かないため、計画的な入れ替えが必要です。
- **関連語**: [ディストリビューション](#g-os-distribution)、[Ubuntu と Red Hat 系](#g-os-ubuntu-redhat)、脆弱性対応（別章）
- **確かめかた**: Ubuntu なら `cat /etc/os-release` の `VERSION` 行に LTS の表記が出ます。LTS という言い方をしない配布物もあるため、期限は配布元の公式サイトで確認します。

<a id="g-os-eol"></a>
## EOL（イー・オー・エル）

- **一言**: 修正やサポートの提供が打ち切られる、製品の保守期限のことです。
- **たとえ**: 自動車の部品供給が終わる時期です。走れはしますが、壊れても直す部品が届きません。
- **くわしく**: End of Life の略で、日本語では保守終了や提供終了と呼びます。この日を過ぎると、弱点（脆弱性）が見つかっても修正が配られなくなります。動くことは動くものの、攻撃の的になりやすく、取引先や監査の基準で利用を止められることもあります。入れ替えには検証と作業の時間が要るので、期限の 1 年ほど前から計画を立てます。
- **覚え方**: End of Life は「一生の終わり」で、面倒を見てもらえる期間の最終日だと覚えます。
- **まちがえやすい**: 期限が来ても動き続けるため、問題ないと誤解されがちです。動いていることと守られていることは別で、放置するほど危険が積み上がります。
- **関連語**: [LTS](#g-os-lts)、[ディストリビューション](#g-os-distribution)、脆弱性対応（別章）
- **確かめかた**: `cat /etc/os-release` で版を確認し、その版の期限は配布元の公式サイトで調べます。Ubuntu では `ubuntu-security-status` で、サポート対象外のソフトの数も分かります。

<a id="g-os-windows-server"></a>
## Windows Server（ウィンドウズ サーバー）

- **一言**: Microsoft 社のサーバー向け OS で、社内のアカウント管理が得意です。
- **たとえ**: 会社の総務部のような OS です。社員名簿（アカウント）と部屋の鍵（権限）をまとめて引き受けます。
- **くわしく**: 普段の Windows と似た操作感で、サーバー向けの機能を提供する OS です。社内のアカウントをまとめて管理する Active Directory、ファイル共有、業務アプリの土台としてよく使われます。画面（GUI）付きの構成のほかに画面を持たない構成も選べ、管理は PowerShell というコマンドの仕組みでも行えます。
- **覚え方**: 「Windows Server といえば Active Directory（社内の住所録）」と、代表機能とセットで覚えます。
- **まちがえやすい**: 手元の Windows と同じ感覚で扱いがちですが、ライセンスの数え方や機能の追加手順が異なります。動かせるアプリの前提も別物です。
- **関連語**: [OS](#g-os-os)、[CLI と GUI](#g-os-cli-gui)、[サービス](#g-os-service)
- **確かめかた**: `winver` で版が表示されます。PowerShell では `Get-ComputerInfo` で構成を確認できます。

<a id="g-os-ad-ldap"></a>
## Active Directory と LDAP（アクティブ ディレクトリ ／ エル・ディー・エー・ピー）

- **一言**: 利用者や機器の情報を 1 か所にまとめ、認証もそこに任せる仕組みです。
- **たとえ**: 会社の社員名簿と入館証の発行窓口です。誰がどの部屋に入れるかも、名簿の側で決めます。
- **くわしく**: LDAP は、人や機器の情報を階層状に並べた台帳を読み書きするための決まりごとです。Active Directory は Microsoft 社がこの考え方を土台に作った仕組みで、Windows Server の代表的な役割です。利用者は 1 組の ID とパスワードで社内の複数のサーバーに入れ、担当者は退職者の停止を 1 か所の操作で済ませられます。Linux も同じ台帳を参照させれば、共通のアカウントでログインできます。
- **覚え方**: directory は「住所録」なので、社内の住所録を 1 冊にまとめる仕組みだと覚えます。
- **まちがえやすい**: ファイルを入れるフォルダ（ディレクトリ）とは別の意味です。ここでの台帳は、人や機器の情報を集めたものを指します。
- **関連語**: [Windows Server](#g-os-windows-server)、[サービス](#g-os-service)、DNS（別章）、シングルサインオン／SSO（11 章）、Kerberos（11 章）
- **確かめかた**: Windows Server では PowerShell の `Get-ADDomain` で参加先の情報が出ます。Linux から参加の状況を見るときは `realm list` を使います。

<a id="g-os-package-manager"></a>
## パッケージマネージャ

- **一言**: ソフトの導入・更新・削除を、必要な部品ごとまとめて扱う仕組みです。
- **たとえ**: スマホのアプリストアです。1 つ入れれば必要な部品も一緒に届き、後からまとめて更新できます。
- **くわしく**: Debian 系は `apt`、Red Hat 系は `dnf`（古い版では `yum`）を使います。どちらも配布元の倉庫（リポジトリ）からソフトを取り寄せます。動かすために必要な関連ソフトを自動でそろえ、どの版が入っているかを台帳として記録します。手でファイルを置く方式より、後の更新と撤去がずっと楽になります。
- **覚え方**: package は「小包」、manager は「管理人」。ソフトの宅配係と台帳係だと覚えます。
- **まちがえやすい**: ネットから落とした実行ファイルを直接置くと、台帳に載らないため更新から漏れます。原則はパッケージマネージャ経由で入れます。
- **関連語**: [ディストリビューション](#g-os-distribution)、[Ubuntu と Red Hat 系](#g-os-ubuntu-redhat)、[LTS](#g-os-lts)
- **確かめかた**: 導入済みの一覧は `apt list --installed`（Debian 系）や `rpm -qa`（Red Hat 系）で確認できます。

<a id="g-os-shell"></a>
## シェル

- **一言**: 打ったコマンドを受け取り、OS に伝えて結果を返す通訳役のプログラムです。
- **たとえ**: 海外旅行の通訳ガイドです。「これがほしい」を現地の言葉に直して伝え、返事を持ち帰ってくれます。
- **くわしく**: Linux では bash や zsh がよく使われます。コマンドの解釈だけでなく、変数・繰り返し・条件分岐も書けるので、作業手順をまとめた台本（シェルスクリプト）を作れます。ログインするとまずシェルが動き、そこから他のプログラムが呼び出されます。
- **覚え方**: shell は「殻」。核（カーネル）を包む外側で、人が触るのは殻の側だと覚えます。
- **まちがえやすい**: ターミナルとシェルは別物です。ターミナルは文字を映す画面、その中で動いている中身がシェルです。
- **関連語**: [ターミナルとコンソール](#g-os-terminal-console)、[コマンドと引数・オプション](#g-os-command-argument-option)、[カーネル](#g-os-kernel)
- **確かめかた**: `echo $SHELL` はログイン時の既定のシェル、`ps -p $$ -o comm=` は今動いているシェルを表示します。使えるシェルの一覧は `cat /etc/shells` で見られます。

<a id="g-os-cli-gui"></a>
## CLI と GUI（シー・エル・アイ ／ ジー・ユー・アイ）

- **一言**: CLI は文字で命令する方式、GUI は画面を見て操作する方式です。
- **たとえ**: CLI は電話で頼む出前、GUI は写真つきメニューを指さす店内注文です。慣れると電話のほうが速く、履歴も残ります。
- **くわしく**: CLI は Command Line Interface の略で、キーボードから文字で指示します。GUI は Graphical User Interface の略で、マウスでボタンやアイコンを操作します。サーバーは画面をつながない機械が多く、手順を文字で残して自動化できる CLI が主役になります。
- **覚え方**: C は Command で「打つ」、G は Graphical で「絵で選ぶ」。頭文字が入口の形を表します。
- **まちがえやすい**: 「GUI が初心者用、CLI が上級者用」という分け方は誤りです。CLI は同じ手順を確実に繰り返せるので、現場ではむしろ基本の道具です。
- **関連語**: [シェル](#g-os-shell)、[ターミナルとコンソール](#g-os-terminal-console)、[Windows Server](#g-os-windows-server)
- **確かめかた**: `systemctl get-default` を打ちます。`graphical.target` なら画面付き、`multi-user.target` なら文字中心の設定です。

<a id="g-os-terminal-console"></a>
## ターミナルとコンソール

- **一言**: ターミナルは文字をやり取りする画面、コンソールは機械に直結した操作口です。
- **たとえ**: ターミナルは自宅からかける電話、コンソールはビルの受付に置かれた内線機です。電話が不通でも、受付まで行けば話せます。
- **くわしく**: ターミナル（端末）はシェルと文字をやり取りする窓で、手元の端末アプリも遠隔接続の画面も含みます。コンソールは本体に直接つながる操作口です。クラウドでは、管理画面から開けるシリアルコンソールが近い役割になります。ネットワークが切れて遠隔接続できないとき、最後の頼みの綱になります。
- **覚え方**: terminal は「終端の窓口」、console は「本体の操作卓」。機械との距離の違いで覚えます。
- **まちがえやすい**: クラウド事業者の管理用 Web 画面も「コンソール」と呼ばれます。相手がどちらの意味で言っているか、最初に確かめます。
- **関連語**: [シェル](#g-os-shell)、[CLI と GUI](#g-os-cli-gui)、SSH（別章）
- **確かめかた**: `tty` で今つないでいる端末の名前、`who` で誰がどこから入っているかが分かります。

<a id="g-os-command-argument-option"></a>
## コマンドと引数・オプション（コマンド ／ ヒキスウ ／ オプション）

- **一言**: コマンドは命令の名前、引数は対象、オプションは動き方の指定です。
- **たとえ**: クリーニングの注文です。「洗って（コマンド）」「このシャツを（引数）」「急ぎで（オプション）」の 3 点セットになります。
- **くわしく**: `ls -l /etc` なら、`ls` がコマンド、`/etc` が引数、`-l` がオプションです。オプションには `-l` のような短い形と `--all` のような長い形があり、同じ意味を別表記で書ける場合が多くあります。引数を省くと、現在地など既定の対象が使われます。
- **覚え方**: 動詞（コマンド）・目的語（引数）・副詞（オプション）の順だと覚えます。
- **まちがえやすい**: 大文字と小文字は区別され、`-r` と `-R` が別の意味を持つコマンドもあります。うろ覚えのまま打たず、`--help` で確認してから実行します。
- **関連語**: [シェル](#g-os-shell)、[終了コード](#g-os-exit-code)、[リダイレクトとパイプ](#g-os-redirect-pipe)
- **確かめかた**: `ls --help` や `man ls` で、使える引数とオプションの説明が読めます。

<a id="g-os-process"></a>
## プロセス

- **一言**: 起動して今まさに動いている、プログラム 1 つ 1 つの実体です。
- **たとえ**: 楽譜（プログラム）と、いま鳴っている演奏（プロセス）の関係です。同じ楽譜から、別々の演奏を同時に始められます。
- **くわしく**: ディスク上のファイルが「プログラム」、それをメモリに読み込んで実行している状態が「プロセス」です。プロセスごとに専用のメモリ領域と番号が割り当てられ、互いのメモリを直接のぞくことはできません。1 つのプログラムから複数のプロセスを同時に動かすこともできます。
- **覚え方**: プログラムは名詞（置いてあるファイル）、プロセスは動詞（動いている状態）だと覚えます。
- **まちがえやすい**: 「入っている（導入済み）」と「動いている（プロセスがある）」は別の話です。導入しただけで起動していなければ、サーバーは応答しません。
- **関連語**: [PID](#g-os-pid)、[デーモン](#g-os-daemon)、[スレッド](#g-os-thread)
- **確かめかた**: `ps aux` で動いているプロセスの一覧が出ます。多すぎるときは `ps aux | head` で先頭だけ見ます。

<a id="g-os-pid"></a>
## PID（ピー・アイ・ディー）

- **一言**: プロセスに 1 つずつ割り振られる、重複しない管理番号です。
- **たとえ**: 病院の受付番号です。同姓同名の患者が何人いても、番号で確実に 1 人を呼び出せます。
- **くわしく**: Process ID の略で、OS がプロセスを見分けるために付ける整数です。同じ名前のプロセスが並んでいても、PID を指定すれば対象を 1 つに絞れます。終了した番号は後から別のプロセスに再利用されるため、古い PID を控えて使い回すのは危険です。
- **覚え方**: コインロッカーの鍵番号と同じで、その場かぎりの整理番号。返せばまた別の人に配られます。
- **まちがえやすい**: PID はサーバーの再起動やプロセスの起動し直しのたびに変わります。手順書に固定の PID を書かず、名前から調べ直します。
- **関連語**: [プロセス](#g-os-process)、[親プロセスと子プロセス](#g-os-parent-child-process)、[init と PID 1](#g-os-init-pid1)
- **確かめかた**: `echo $$` で今のシェルの PID が出ます。名前から調べるときは `pgrep -a sshd` のように打ちます。対象の名前は環境によって異なります。

<a id="g-os-parent-child-process"></a>
## 親プロセスと子プロセス（オヤプロセス ／ コプロセス）

- **一言**: あるプロセスが生み出した相手が子、生み出した側が親という関係です。
- **たとえ**: 家系図です。どのプロセスにも必ず親がいて、たどっていくと最初の 1 つにたどり着きます。
- **くわしく**: プロセスは自分の複製を作り、その中身を別のプログラムに入れ替える形で新しいプロセスを起動します。子には親の番号が PPID（親の PID）として記録され、親は子の終了と結果を受け取ります。親が先に終わってしまった子は、原則として PID 1 のプロセスが引き取ります。
- **覚え方**: PID は自分、PPID は親（Parent）。P が 1 つ増えたら親です。
- **まちがえやすい**: ターミナルを閉じると、そこから起動した処理まで一緒に止まることがあります。長時間の処理を「画面を開いたまま放置」で走らせるのは危険です。
- **関連語**: [PID](#g-os-pid)、[プロセス](#g-os-process)、[init と PID 1](#g-os-init-pid1)
- **確かめかた**: `ps -ef` の `PPID` 列で親をたどれます。`pstree -p` が使える環境なら、親子の枝分かれを図で見られます。

<a id="g-os-thread"></a>
## スレッド

- **一言**: 1 つのプロセスの中で、並行して進む作業の流れの単位です。
- **たとえ**: 1 つの事務室で複数の担当が同時に働く形です。机（メモリ）は共用なので、同じ書類を同時に触ると混乱します。
- **くわしく**: プロセスがメモリ空間ごと分かれるのに対し、スレッドは同じプロセスのメモリを共有したまま並行に動きます。共有するぶん切り替えが軽く、Web サーバーやデータベースは多数のスレッドで同時接続をさばきます。共有部分の取り合いが起きるため、順番の制御はプログラム側の仕事です。
- **覚え方**: thread は「糸」。1 つのプロセスから何本もの糸が伸びる姿で覚えます。
- **まちがえやすい**: 「スレッドを増やせば必ず速くなる」は誤りです。CPU の数を超えると切り替えの手間が増え、かえって遅くなることがあります。
- **関連語**: [プロセス](#g-os-process)、[PID](#g-os-pid)、CPU（別章）
- **確かめかた**: `ps -eLf` でスレッドまで含めた一覧が出ます。`top -H` はスレッド単位の表示になります（`q` で終了します）。

<a id="g-os-daemon"></a>
## デーモン

- **一言**: 画面を持たず、裏でずっと待機し続ける常駐プログラムです。
- **たとえ**: マンションの管理人室です。誰も来なくても常駐していて、呼び鈴が鳴った瞬間に対応します。
- **くわしく**: Linux では待ち受け続けるプログラムに、`sshd` や `httpd` のように末尾へ d を付ける習慣があります。端末から切り離されて動くため、作業者がログアウトしても止まりません。要求が来るまで静かに待ち、応答したらまた待機に戻ります。
- **覚え方**: 末尾の d は daemon の d。`sshd` は「ssh の常駐係」だと覚えます。
- **まちがえやすい**: `ssh` と `sshd` は別物です。`ssh` は接続しに行く側の道具、`sshd` は接続を待ち受ける常駐側です。
- **関連語**: [サービス](#g-os-service)、[systemd](#g-os-systemd)、[プロセス](#g-os-process)
- **確かめかた**: `ps -ef` を見て、`TTY` 列が `?` になっているものが端末を持たない常駐プロセスです。

<a id="g-os-service"></a>
## サービス

- **一言**: OS に登録して、起動や停止をまとめて管理してもらう機能の単位です。
- **たとえ**: ビルに入っているテナント店舗です。ビル側（OS）が開店・閉店・営業中かどうかをまとめて把握しています。
- **くわしく**: Linux では、起動のしかたを書いた設定ファイル（ユニット）を systemd に登録します。登録すると、名前を指定するだけで操作できます。開始・停止・状態確認のほか、異常終了したときに自動で立て直す設定も書けます。Windows Server にも同じ考え方の「サービス」があります。
- **覚え方**: デーモンは「中身」、サービスは「登録名」。名札の付いたデーモンだと覚えます。
- **まちがえやすい**: サービス名は配布物によって違います。Web サーバーの Apache は、Debian 系では `apache2`、Red Hat 系では `httpd` という名前です。操作の前に一覧で確かめます。
- **関連語**: [systemd](#g-os-systemd)、[デーモン](#g-os-daemon)、[自動起動と起動](#g-os-enable-start)
- **確かめかた**: `systemctl list-units --type=service` で、今動いているサービスの一覧が出ます。

<a id="g-os-systemd"></a>
## systemd（システムディー）

- **一言**: 多くの Linux で起動とサービス管理を担う、標準の仕組みです。
- **たとえ**: 商業施設の開店準備を仕切る司令塔です。電気・空調・各店舗を、順番と依存関係を見ながら立ち上げます。
- **くわしく**: systemd は最初のプロセスとして起動し、必要なサービスを依存関係に従って並行に立ち上げます。操作は `systemctl`、ログの確認は `journalctl` という道具で行います。ユニットという設定ファイル 1 枚に、起動方法・再起動の条件・依存関係をまとめて書けます。
- **覚え方**: systemctl は system control の略。systemd を操作するリモコンだと覚えます。
- **まちがえやすい**: `systemd` と `systemctl` を混同しがちです。`systemd` が本体、`systemctl` はそれに指示を出すコマンドです。
- **関連語**: [サービス](#g-os-service)、[init と PID 1](#g-os-init-pid1)、[自動起動と起動](#g-os-enable-start)
- **確かめかた**: `systemctl --version` で版が出ます。`ps -p 1 -o comm=` で最初のプロセスが systemd かも確認できます。

<a id="g-os-init-pid1"></a>
## init と PID 1（イニット ／ ピー・アイ・ディー ワン）

- **一言**: OS の起動後に最初に動き、すべてのプロセスの先祖になる 1 番のプロセスです。
- **たとえ**: 開店前に一番乗りで鍵を開ける店長です。他の従業員（プロセス）は全員、この人の下から出勤していきます。
- **くわしく**: カーネルは自分の準備を終えると、最初のプロセスを 1 つ起動します。これに PID 1 が付き、多くの Linux ではその中身が systemd です。以降のサービスはすべてこの子孫として立ち上がり、親を失った子プロセスも PID 1 が引き取って後始末をします。
- **覚え方**: PID 1 は「鍵を開ける店長」。全プロセスの出発点だと覚えます。
- **まちがえやすい**: PID 1 は普通のプロセスと同じようには止められません。終わればシステム全体が止まるため、OS が特別に扱っています。
- **関連語**: [systemd](#g-os-systemd)、[PID](#g-os-pid)、[親プロセスと子プロセス](#g-os-parent-child-process)
- **確かめかた**: `ps -p 1 -o pid,comm` で PID 1 の中身が見られます。表示は環境によって異なります。

<a id="g-os-enable-start"></a>
## 自動起動と起動（ジドウキドウ ／ キドウ）

- **一言**: enable は次回以降も自動で立ち上げる設定、start は今すぐ動かす操作です。
- **たとえ**: 目覚まし時計です。今この場で鳴らす（start）のと、毎朝鳴るようセットする（enable）のは別の操作です。
- **くわしく**: `systemctl start` は今この場でサービスを開始しますが、設定は残らず次の再起動では立ち上がりません。`systemctl enable` は OS の起動時に自動で開始する予約で、今すぐ動き出すわけではありません。両方まとめたいときは `systemctl enable --now` のように指定します。
- **覚え方**: start は「今だけ」、enable は「これから毎回」。時間軸で分けます。
- **まちがえやすい**: start だけで安心してしまい、サーバー再起動後にサービスが落ちたまま、という事故が定番です。作業後は自動起動の設定も必ず確認します。
- **関連語**: [systemd](#g-os-systemd)、[サービス](#g-os-service)、[デーモン](#g-os-daemon)
- **確かめかた**: `systemctl is-enabled <サービス名>` で自動起動の有無を確認します。今動いているかは `systemctl is-active <サービス名>` で分かります。

<a id="g-os-restart-reload"></a>
## restart と reload（リスタート ／ リロード）

- **一言**: restart は止めて起動し直す操作、reload は動かしたまま設定を読み直します。
- **たとえ**: お店の模様替えです。restart は一度シャッターを閉めて開け直す形、reload は開けたまま貼り紙だけ差し替える形です。
- **くわしく**: 設定ファイルを書き換えても、動いているプログラムは古い内容を持ったままです。restart はプロセスを終了して新しく起動するため、その間は接続を受け付けられません。reload は動作を続けたまま設定だけを読み直すので、利用者から見て止まる時間がありません。ただし reload に対応していないソフトや、reload では反映されない設定項目もあります。
- **覚え方**: load は「読み込む」なので、reload は読み直すだけ、restart は起動からやり直しだと覚えます。
- **まちがえやすい**: reload なら必ず無停止と思いがちですが、対応していないソフトでは何も起きないことがあります。反映されるかどうかは、作業前に公式資料で確かめます。
- **関連語**: [サービス](#g-os-service)、[自動起動と起動](#g-os-enable-start)、[シグナル](#g-os-signal)
- **確かめかた**: `systemctl show <サービス名> -p CanReload` で、reload に対応しているかが分かります。設定を読み直した時刻は `systemctl status <サービス名>` の表示でも追えます。

<a id="g-os-env-var"></a>
## 環境変数（カンキョウヘンスウ）

- **一言**: 起動するプログラムに引き渡される、名前付きの設定値の入れ物です。
- **たとえ**: 引き継ぎメモを貼った付箋です。親から子へそのまま手渡され、受け取った側が読んで動きを変えます。
- **くわしく**: `PATH` はコマンドを探す場所の一覧、`LANG` は表示言語というように、名前と値の組で環境を伝えます。シェルで設定した値は、そこから起動した子プロセスへ引き継がれます。接続先の指定や動作モードの切り替えにもよく使われます。
- **覚え方**: プログラムに持たせる「持ち物リスト」。中身は `echo $名前` でのぞけます。
- **まちがえやすい**: シェルで設定した環境変数は、そのシェルとその子だけに効きます。別の端末や、systemd から起動したサービスには届きません。
- **関連語**: [シェル](#g-os-shell)、[親プロセスと子プロセス](#g-os-parent-child-process)、[コマンドと引数・オプション](#g-os-command-argument-option)
- **確かめかた**: `printenv` で一覧、`echo $PATH` で 1 つの値だけ確認できます。

<a id="g-os-exit-code"></a>
## 終了コード（シュウリョウコード）

- **一言**: プロセスが終わるときに残す、成否を表す 0 から 255 の数値です。
- **たとえ**: 配達員の報告書です。「渡せました（0）」「不在でした（0 以外）」と、数字だけで結果を返します。
- **くわしく**: 0 が成功、0 以外が失敗という約束で、失敗の理由ごとに違う数字を返すコマンドもあります。シェルは直前の終了コードを `$?` に覚えており、`&&` や `||` の分岐判断にも使われます。監視や自動処理の仕組みは、この数値を見て成否を判定します。
- **覚え方**: 0 は「問題ゼロ」。それ以外は何かあった合図です。
- **まちがえやすい**: 画面にエラーらしき文字が出ていても、終了コードが 0 なら仕組みの上では成功扱いです。自動処理では見た目ではなく `$?` で判断します。
- **関連語**: [コマンドと引数・オプション](#g-os-command-argument-option)、[標準入力・標準出力・標準エラー出力](#g-os-stdio)、[プロセス](#g-os-process)
- **確かめかた**: `ls /` を実行した直後に `echo $?` と打つと、`0` が返ります。

<a id="g-os-stdio"></a>
## 標準入力・標準出力・標準エラー出力（ヒョウジュンニュウリョク ／ ヒョウジュンシュツリョク ／ ヒョウジュンエラーシュツリョク）

- **一言**: プログラムに最初から用意された、入口 1 本と出口 2 本の通り道です。
- **たとえ**: 屋台の受け渡し口です。注文を受ける口、料理を出す口、苦情を伝える口が別々に付いています。
- **くわしく**: 標準入力（番号 0）はキーボードなどからの入力、標準出力（1）は通常の結果、標準エラー出力（2）は警告やエラーの通り道です。出口が 2 本に分かれているので、結果だけをファイルに残しつつエラーは画面に出す、といった使い分けができます。0・1・2 の番号は、リダイレクトの指定でそのまま使います。
- **覚え方**: 0 は入る、1 は出る、2 は文句。番号順に「入・出・エラー」です。
- **まちがえやすい**: `>` でファイルに保存されるのは標準出力だけで、エラーは画面に残ります。エラーも記録したいときは `2>` を別に指定します。
- **関連語**: [リダイレクトとパイプ](#g-os-redirect-pipe)、[終了コード](#g-os-exit-code)、[シェル](#g-os-shell)
- **確かめかた**: `ls /nosuchdir` と打つとエラーが出ます。`ls /nosuchdir 2>/dev/null` にすると、エラーだけ消えて何も表示されません。

<a id="g-os-redirect-pipe"></a>
## リダイレクトとパイプ

- **一言**: リダイレクトは出力先の付け替え、パイプは次のコマンドへの受け渡しです。
- **たとえ**: リダイレクトはホースの先をバケツに向ける操作、パイプは 2 本のホースを直結して流し続ける操作です。
- **くわしく**: `>` は出力をファイルへ上書き、`>>` は末尾へ追記、`<` はファイルを入力として読み込みます。`|`（パイプ）は左のコマンドの標準出力を、右のコマンドの標準入力へつなぎます。小さなコマンドをつないで必要な情報だけ取り出せるのが、Linux の強みです。
- **覚え方**: 矢印はファイルへ、縦棒はコマンドへ。向き先で覚えます。
- **まちがえやすい**: `>` は既存ファイルの中身を確認なしで上書きします。残したいときは `>>` を使い、書き込み先のファイル名は指を止めて確認します。
- **関連語**: [標準入力・標準出力・標準エラー出力](#g-os-stdio)、[シェル](#g-os-shell)、[コマンドと引数・オプション](#g-os-command-argument-option)
- **確かめかた**: `ls /etc | head -n 5` で先頭 5 行だけ、`ps aux | wc -l` で行数だけが表示されます。

<a id="g-os-foreground-background"></a>
## フォアグラウンドとバックグラウンド

- **一言**: 画面を占有して動かすのがフォアグラウンド、裏で動かすのがバックグラウンドです。
- **たとえ**: 洗濯機の前で回り終わるのを見張るのがフォアグラウンド、回しっぱなしで掃除に移るのがバックグラウンドです。
- **くわしく**: フォアグラウンドで動かすと、そのコマンドが終わるまでシェルは次の入力を受け付けません。末尾に `&` を付けるとバックグラウンドで動き、すぐ次のコマンドを打てます。ただし端末との縁は残るため、長時間の処理はサービスとして登録するほうが確実です。
- **覚え方**: `&` は「後ろでよろしく」の記号。付ければ裏方に回ります。
- **まちがえやすい**: バックグラウンドにしても端末から完全に切り離されるとは限りません。ログアウトで止まることがあるので、何時間もかかる処理には向きません。
- **関連語**: [シェル](#g-os-shell)、[プロセス](#g-os-process)、[サービス](#g-os-service)
- **確かめかた**: `sleep 30 &` と打った後に `jobs` を実行すると、裏で動いている処理が一覧に出ます。

<a id="g-os-signal"></a>
## シグナル

- **一言**: 動いているプロセスへ外から送る、短い合図の仕組みです。
- **たとえ**: 「そろそろ片付けて」と肩をたたくのと、電源プラグを抜くのとの違いです。後始末の丁寧さがまるで変わります。
- **くわしく**: `Ctrl` と `C` の同時押しは、動作中のプロセスに中断の合図（SIGINT）を送る操作です。SIGTERM は「片付けて終了して」という穏やかな依頼です。SIGKILL は問答無用の強制終了で、受け取る側は無視も後始末もできません。設定の読み込み直しに SIGHUP を使うソフトもあります。
- **覚え方**: TERM は「お願い」、KILL は「強制」。まずお願いから、と覚えます。
- **まちがえやすい**: 強制終了すると、書きかけのデータや残骸のファイルが残ることがあります。まず正規の停止手順を試し、強制は最後の手段にします。
- **関連語**: [プロセス](#g-os-process)、[PID](#g-os-pid)、[フォアグラウンドとバックグラウンド](#g-os-foreground-background)
- **確かめかた**: `kill -l` と打つと、送れるシグナルの名前の一覧が表示されます（送信はしません）。

<a id="g-os-oom-killer"></a>
## OOM Killer（オー・オー・エム キラー）

- **一言**: メモリが足りないとき、カーネルがプロセスを選んで強制終了する仕組みです。
- **たとえ**: 定員を超えた満員のエレベーターです。誰かに降りてもらわないと、全員が動けません。
- **くわしく**: メモリを使い切ると新しい割り当てができず、機械全体が止まりかねません。そこでカーネルは、使用量や重要度から点数を付け、点数の高いプロセスを終了させます。選ばれやすいのはメモリを最も多く使っているもので、多くの場合それが主役のアプリです。強制終了の合図で消されるため、対象は後始末もお別れの記録も残せません。
- **覚え方**: OOM は Out Of Memory の頭文字で、メモリ切れの後始末係だと覚えます。
- **まちがえやすい**: アプリ自身の不具合で落ちたと思われがちです。カーネルの記録に `Out of memory` の行があれば原因はメモリ不足で、見直す先はアプリの設定か搭載メモリの量です。
- **関連語**: [シグナル](#g-os-signal)、[プロセス](#g-os-process)、メモリ（別章）
- **確かめかた**: `dmesg -T | grep -i "killed process"` で発生の記録が探せます。`journalctl -k | grep -i oom` でも同じ内容を確認できます。

<a id="g-os-bit-width"></a>
## 32 bit と 64 bit（サンジュウニ ビット ／ ロクジュウヨン ビット）

- **一言**: CPU と OS が一度に扱えるデータの幅で、扱えるメモリ量も変わります。
- **たとえ**: 道路の車線数です。64 bit は車線が広く、一度に運べる荷物（メモリ）の量が桁違いになります。
- **くわしく**: 32 bit ではメモリの住所の幅が足りず、1 つのプロセスが扱えるメモリはおよそ 4 GB が上限になります。実際に使える量は環境によって異なります。64 bit ではこの制約が実質なくなり、今のサーバー向け OS とソフトはほぼ 64 bit 向けに提供されます。
- **覚え方**: `x86_64` や `amd64` は 64 bit、`i386` や `i686` は 32 bit の目印です。
- **まちがえやすい**: 64 bit ならどれでも動くと思いがちですが、`x86_64` 用と `aarch64`（Arm）用は別物です。同じ 64 bit でも、そのままでは動きません。
- **関連語**: [OS](#g-os-os)、[カーネル](#g-os-kernel)、[パッケージマネージャ](#g-os-package-manager)
- **確かめかた**: `uname -m` で `x86_64` などの種別、`getconf LONG_BIT` で 32 か 64 かが表示されます。
