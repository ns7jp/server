# 一問一答（50 問）

問題を読んだら、解答例を見ないで声に出して答えてみてください。1 グループ 10 問のうち 7 問ほど答えられたら、次の章へ進んで大丈夫です。

## 基礎とハードウェア（Q1〜Q10）

1. サーバーとクライアントのちがいを説明してください。
2. Web サーバーとファイルサーバーは、それぞれ何を提供しますか。
3. CPU とメモリは、それぞれどんな役割を持ちますか。
4. メモリとストレージのちがいは何ですか。
5. ラックマウント型サーバーの「1U」は何を表していますか。
6. サーバー機に電源ユニットが 2 つ付いていることが多いのはなぜですか。
7. RAID とは何をするしくみですか。
8. RAID 1 と RAID 0 のちがいは何ですか。
9. IPMI や BMC のような遠隔管理のしくみは、どんなときに使いますか。
10. 「サーバーが重い」と言われたとき、まずどの資源を見ますか。

<details>

<summary>解答例</summary>

1. クライアントはサービスを頼む側、サーバーは頼まれて応える側です。役割の呼び名なので、1 台の機械が場面によって両方になることもあります。
2. Web サーバーは Web ページやアプリの画面を返します。ファイルサーバーは共有の置き場として、ファイルの保存と取り出しを引き受けます。
3. CPU は計算や判断を行う頭脳にあたります。メモリは作業中のデータを広げる机で、広いほど同時に多くの処理を扱えます。
4. メモリは電源を切ると内容が消える一時置き場です。ストレージは電源を切っても残る保管場所で、読み書きの速さはメモリより遅くなります。
5. ラックに取り付けるときの高さの単位です。1U が基準の高さで、2U はその 2 倍の高さになります。
6. 片方が壊れても、もう片方だけで動き続けるためです。そこが壊れると全体が止まる箇所（単一障害点）を減らす、代表的な備えです。
7. 複数のディスクをまとめて 1 つのように扱うしくみです。壊れても使い続けられるようにしたり、読み書きを速くしたりする目的で使います。
8. RAID 1 は同じ内容を 2 台に書くので、1 台壊れても動き続けられます。RAID 0 は分けて書くので速くなりますが、1 台壊れると全体が読めなくなります。
9. OS が起動しないときや、現地へ行かずに機器を操作したいときに使います。BMC は本体とは別に動く管理用の部品で、IPMI はそれをやりとりする決まりごとです。本体の OS が止まっていても手が届きます。
10. CPU、メモリ、ディスクの読み書き、ネットワークの 4 つを順に見ます。どこが詰まっているかで、打つ手がまったく変わるためです。

</details>

## Linux と OS（Q11〜Q20）

11. OS の役割を一言で説明してください。
12. プロセスとは何ですか。
13. CUI と GUI のちがいは何ですか。サーバーではどちらが中心ですか。
14. デーモン（常駐サービス）とは何ですか。
15. 絶対パスと相対パスのちがいは何ですか。
16. `/etc` `/var` `/home` には、それぞれ何が置かれますか。
17. パーミッションの「rwx」は何を表していますか。
18. root ユーザーと一般ユーザーを分けて使うのはなぜですか。
19. パッケージ管理のしくみは、何を楽にしてくれますか。
20. ディスクの空き容量を確かめたいとき、どこを見ますか。

<details>

<summary>解答例</summary>

11. ハードウェアとアプリの間に立ち、機器の力を分け合う土台のソフトです。CPU やメモリを誰にどれだけ渡すかを決めています。
12. 実行中のプログラム 1 つ 1 つのことです。同じプログラムを 2 回起動すれば、プロセスは 2 つになります。
13. CUI は文字で命令する操作方法、GUI は画面上のアイコンを操作する方法です。サーバーは CUI が中心で、手順を文字で残して再現しやすいのが利点です。
14. 裏側でずっと動き続け、要求が来るのを待っているプログラムです。Web サーバーやデータベースのように、いつでも応答する必要があるものが該当します。
15. 絶対パスは `/` から始まる住所で、どこにいても同じ場所を指します。相対パスは今いる場所からの道順なので、現在地が変わると指す先も変わります。
16. `/etc` は設定ファイル、`/var` はログなど増えていくデータ、`/home` は一般ユーザーの作業場所です。役割ごとに分かれているので、探す場所の見当がつきます。
17. r は読み取り、w は書き込み、x は実行の許可です。所有者・グループ・その他の 3 つに分けて設定します。
18. 誤操作や不正操作の影響を小さくするためです。root は何でもできてしまうので、普段は権限の小さい一般ユーザーで作業します。
19. ソフトの導入や更新を、いっしょに必要になるソフトごとまとめて引き受けてくれます。入れたものの一覧が残るので、今の状態を後から確かめられます。
20. `df -h` で全体の空き容量を確認します。場所ごとの内訳は `du -sh /var/log` のように場所を指定して調べます。どちらも中身を変えない、表示するだけのコマンドです。

</details>

## ネットワーク（Q21〜Q30）

21. IP アドレスは何のためにありますか。
22. プライベート IP アドレスとグローバル IP アドレスのちがいは何ですか。
23. サブネットマスクは何を決めていますか。
24. デフォルトゲートウェイの役割は何ですか。
25. ポート番号は何のためにありますか。
26. TCP と UDP のちがいは何ですか。
27. DNS は何をするしくみですか。
28. DHCP と固定 IP のちがいは何ですか。サーバーではどちらが基本ですか。
29. SSH は何のために使いますか。
30. 「サイトにつながらない」と言われたとき、どんな順で切り分けますか。

<details>

<summary>解答例</summary>

21. ネットワーク上の機器を見分けるための住所です。宛先が分からなければ、データを届ける先を決められません。
22. プライベート IP は社内や家庭内だけで通じる住所、グローバル IP はインターネット全体で通じる住所です。外に出るときは、途中で変換して通信します。
23. IP アドレスのうち、どこまでが同じネットワークの仲間かを決めています。仲間の内か外かで、直接届けるか出口へ渡すかが変わります。
24. 自分のネットワークの外へ出るときの出口です。宛先が同じネットワークにいない通信は、いったんここへ渡します。
25. 同じ機器の中で、どのサービス宛ての通信かを区別するためです。住所が建物なら、ポート番号は部屋番号にあたります。
26. TCP は届いたかを確認しながら送るので確実ですが、やりとりは増えます。UDP は確認をしない分だけ軽く、速さを優先する通信で使われます。
27. ドメイン名を IP アドレスに変換するしくみです。人は名前で覚え、機械は番号で届けるので、その橋渡しが必要になります。
28. DHCP は IP アドレスを自動で借りる方式、固定 IP は決め打ちで設定する方式です。サーバーは住所が変わると接続先が分からなくなるため、固定が基本です。
29. 遠くにあるサーバーへ安全にログインし、コマンドで操作するために使います。通信が暗号化されるので、途中で内容を読み取られにくくなります。
30. 名前解決ができるか、相手まで届くか、ポートが応答するか、アプリのログはどうか、の順に確認します。どこで止まっているかが分かれば、原因の範囲を絞れます。

</details>

## Web・データ・仮想化（Q31〜Q40）

31. HTTP と HTTPS のちがいは何ですか。
32. Web サーバーとアプリケーションサーバーは、役割がどうちがいますか。
33. リバースプロキシは何をするものですか。
34. ステータスコード 404 と 500 は、それぞれ何を示していますか。
35. データベースは、ファイルにそのまま保存するのと何がちがいますか。
36. SQL とは何ですか。
37. バックアップとレプリケーション（複製）のちがいは何ですか。
38. リストア（復元）の練習をしておくべきなのはなぜですか。
39. 仮想マシンとコンテナのちがいは何ですか。
40. オンプレミスとクラウドのちがいを、費用の考え方から説明してください。

<details>

<summary>解答例</summary>

31. HTTPS は HTTP のやりとりを暗号化したものです。途中で内容を見られたり書き換えられたりしにくくなるため、今はこちらが基本です。
32. Web サーバーは画像や HTML など、あらかじめ用意された内容をそのまま返します。アプリケーションサーバーは、その場で処理をして結果を作ります。
33. 利用者からの通信をいったん受け取り、後ろのサーバーへ渡す代理役です。振り分けや暗号化の窓口をまとめられるので、後ろ側を単純に保てます。
34. 404 は「その場所が見つからない」で、多くは要求した宛先のちがいです。500 はサーバー側の処理で問題が起きた合図なので、まずサーバーのログを見ます。
35. データベースは決まった形でデータを持ち、条件を指定した検索をすぐに行えます。ファイルにそのまま書く方法だと、探すしくみも、同時に書き換えたときの整理も自分で用意することになります。
36. データベースにデータを入れたり探したりするための言語です。「どの表から、どんな条件で」と伝える形で書きます。
37. バックアップは過去のある時点の控えなので、誤って消しても戻せます。レプリケーションは常に同じ内容を別に持つしくみなので、誤って消すと複製側からも消えます。
38. 取れているつもりで戻せない、という失敗が一番多いからです。戻す手順とかかる時間を実際に確かめて、初めて備えになります。
39. 仮想マシンは OS ごと丸ごと用意するので独立性が高く、起動は重めです。コンテナは土台の OS のしくみを共有してアプリだけを包むので、軽くて起動が速くなります。
40. オンプレミスは機器を自分で用意して持ち続ける形です。クラウドは使った分を借りて払う形が中心です。どちらが安く済むかは規模や使い方しだいで、環境によって異なります。

</details>

## 運用・セキュリティ・現場（Q41〜Q50）

41. 可用性とは何ですか。冗長化はそれとどう関係しますか。
42. 単一障害点（SPOF）とは何ですか。
43. スケールアップとスケールアウトのちがいは何ですか。
44. 認証と認可のちがいは何ですか。
45. ファイアウォールは何をするものですか。
46. 最小権限の原則とは何ですか。なぜ守るのですか。
47. 監視とログは、それぞれ何のためにありますか。
48. 障害が起きたとき、復旧と原因究明はどちらを先に進めますか。
49. 本番環境と検証環境を分けるのはなぜですか。
50. 手順書に「作業前の確認」と「切り戻し手順」を書くのはなぜですか。

<details>

<summary>解答例</summary>

41. 止まらずに使い続けられる度合いのことです。冗長化は同じ役割の機器を複数用意する備えで、1 つ壊れても使い続けられるようにします。
42. そこが壊れると全体が止まってしまう、代わりのない箇所のことです。設計のときは、この箇所を洗い出して減らすことを考えます。
43. スケールアップは 1 台の性能を上げる方法、スケールアウトは台数を増やす方法です。台数を増やす方は振り分けのしくみが要りますが、上限を伸ばしやすくなります。
44. 認証は「誰か」を確かめること、認可は「何をしてよいか」を決めることです。ログインできたからといって、すべての操作が許されるわけではありません。
45. 通信を通す・通さないを決める関所です。使う予定のない入口を閉じておくと、攻撃を受ける面を小さくできます。
46. 必要な人に、必要な範囲の権限だけを渡す考え方です。事故や乗っ取りが起きても、影響が届く範囲を狭くできます。
47. 監視は異常に早く気づくため、ログは何が起きたかを後から追うためにあります。両方そろって、気づいてから原因までたどり着けます。
48. まず復旧を優先し、影響を止めてから原因究明に移ります。ただし調査に必要なログや状態は、消える前に控えておきます。
49. 試した内容が利用者に影響しないようにするためです。手順や設定は検証環境で確かめてから、本番へ持っていきます。
50. 始める前に前提が合っているかを確かめ、うまくいかないときに元へ戻せるようにするためです。戻せる道があると、落ち着いて作業できます。

</details>
