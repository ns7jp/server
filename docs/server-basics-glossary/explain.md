# 覚えた言葉を「使える」状態にする

[用語集の入口](README.md) / [さくいん](index.md) / [前: 確認コマンド逆引き表](commands.md)

言葉を読んで分かることと、人に説明できることは別の力です。用語集を一度読み終えても、いざ口に出すと詰まるのが普通です。ここでは、覚えた言葉を仕事で使える形に変える練習方法をまとめます。

## 30 秒で説明する型

サーバー構成を人に説明するときは、毎回同じ順番で話すと伝わります。次の型の空欄を埋めてから話してください。

```text
【サーバー構成の 30 秒説明テンプレート】
1. 目的  ：この仕組みは（誰）が（何）をするために動いています。
2. 入口  ：利用者は（入口の名前）から入ります。
3. 中身  ：受け取った依頼は（処理する場所）が処理します。
4. 置き場：データは（保存する場所）に置いています。
5. 守り  ：（壊れたときの備え）と（様子を見る仕組み）があります。
6. 現状  ：いまは（できていること）まで、（残っていること）が課題です。
```

埋めた例を 1 つ示します。声に出すと 30 秒ほどになります。

```text
1. 目的  ：社内の申請フォームを、社員が業務時間中に使えるようにしています。
2. 入口  ：利用者は社内向けの URL から入ります。
3. 中身  ：受け取った依頼は Web サーバー 2 台が分担して処理します。
4. 置き場：申請の内容はデータベースサーバーに置いています。
5. 守り  ：定期的なバックアップと、様子を見る監視画面があります。
6. 現状  ：いまは社内からの利用まで、社外からの利用は今後の課題です。
```

空欄に入る言葉は環境によって異なります。まずは自分が触っている環境で埋めてください。台数や置き場所は、自分の目で確かめた事実だけを入れます。

## 用語を説明するときの 4 点セット

用語を 1 つ覚えたら、「1 語・1 役割・1 たとえ・1 確認方法」を声に出します。この 4 つが言えれば、その言葉は使える状態です。たとえだけで終わらせず、必ず確認方法までセットにしてください。

| 用語 | 1 役割（何をするもの） | 1 たとえ | 1 確認方法 |
| --- | --- | --- | --- |
| DNS | 名前を IP アドレス（機械の住所）に変えて教える案内係です | 名前から電話番号を引く電話帳 | `dig example.com` を実行し、返ってきた IP アドレスを見ます |
| ロードバランサー | 届いた依頼を複数の機械に振り分ける受付です | 混んだレジで空いた列に案内する店員 | 管理画面で振り分け先の一覧と、各機械の状態表示を見ます |
| バックアップ | 消えても元に戻せるよう写しを取る仕組みです | 大事な書類のコピーを別の場所に置くこと | 写しの一覧と取得日時、復元テストの記録を見ます |

`dig` が使えない環境では `nslookup example.com` を使います。使える道具や管理画面の見え方は環境によって異なります。復元テストそのものは練習用の環境で、担当者の指示に従って行ってください。

声に出すときは、4 つを短く言い切るつもりで話すと締まります。詰まった項目が、まだ理解できていない場所です。

## 面接や面談で聞かれやすい言い換え

同じ内容でも、聞かれ方は人によって変わります。答えの中心は 1 つに決めておき、言い換えて渡す練習をしてください。

| 聞かれ方 | 何を答えるか | 答えるときの注意 |
| --- | --- | --- |
| サーバーとは何か説明してください | 依頼を受け取って結果を返し続ける役割のことです、と役割から答えます | 機械の形だけの話にせず、その役割を担うソフトも指すと添えます |
| なぜ冗長化が必要ですか | 1 つ壊れても利用者が使い続けられるようにするためです | 「絶対に止まらない」とは言わず、止まりにくくすると答えます |
| 障害時にまず何をしますか | 事実の確認と、関係者への連絡です、と順番で答えます | 原因の推測より先に、現状把握と報告を置きます |
| IP アドレスとドメイン名の違いは | 住所そのものと、覚えやすい名前の違いです | どちらが上位という話ではなく、対応づけの話だと伝えます |
| クラウドとオンプレミスの違いは | 機械を借りて使うか、自分たちで持って置くかの違いです | 価格や性能の優劣を断定せず、目的で選ぶと答えます |
| コンテナや仮想化を知っていますか | どちらも 1 台の機械を分けて使う技術です、と共通点から答えます | 同じものと言い切らず、使った経験の有無も正直に伝えます |
| バックアップと冗長化の違いは | 戻すための備えか、止めないための備えかの違いです | 片方があれば十分、という言い方は避けます |
| Linux は触ったことがありますか | 触った範囲と、そこで何を確認できるかを答えます | 触っていない部分は「これから学びます」と区切ります |
| 監視とは何をすることですか | 決めた項目を見張り、異常なら知らせる仕組みです | 見るだけでなく、知らせる先まで含めて答えます |
| ログは何のために見ますか | いつ何が起きたかを、後から事実で追うためです | 「エラーを探すため」で終えず、記録を残す意味も添えます |
| セキュリティで気をつけていることは | 権限を必要な人だけに絞ることと、記録を残すことです | 覚えた対策名を並べず、日々の行動として話します |
| 作業の前に必ず確認することは | 作業する相手、手順、戻し方、連絡先の 4 つです | 「気をつけます」で終えず、確認する中身を具体的に言います |
| 分からないことがあったらどうしますか | 公式の資料で確かめ、それでも不明なら早めに聞きます | 「調べます」で止めず、確かめる順番まで言います |
| 何か質問はありますか | 入社後に任される範囲や、学ぶ順番を聞きます | 待遇だけを並べず、仕事の中身を先に尋ねます |

## 分からない言葉に出会ったときの調べ方

1. まず 3 つのどれかに仕分けます。機械や部品の話か、役割や仕組みの話か、製品やサービスの名前か。仕分けができると、調べる先が決まります。
2. 公式ドキュメントを一次情報（作った側が出している大元の説明）として当たります。個人が書いた記事は、理解を助ける補助として読みます。
3. 情報の日付と、対象のバージョンを見ます。古い説明が今も正しいとは限りません。書かれていない場合は、参考程度に扱います。
4. 手を動かして確かめます。使うのは、状態を変えない確認コマンドだけです。`ls`、`ping`、`dig`、`curl -I` のような、見るだけの操作から始めます。試す場所は練習用の環境にして、他人が管理するサーバーには許可なく向けません。
5. 自分の言葉で 1 行に書き直します。写した文章ではなく、たとえを 1 つ添えて書きます。書けなければ、まだ分かっていません。
6. 用語ノートに残し、日を置いてもう一度読み返します。読み返して説明できれば、その言葉は身についています。

`curl -I` は、応答の見出しだけを取り出す指定です。これらのコマンドが使えるかどうかは、環境によって異なります。

## やってはいけない覚え方

- 丸暗記だけで終える。言葉は言えても、何をするものか答えられません。
- 実行していないことを実績として話す。読んだだけの内容は「読みました」と伝えます。
- たとえを事実と混同する。たとえは分かりやすくするための例で、仕組みそのものではありません。
- 検索結果の断片だけで判断する。出典と日付を確かめないと、誤りごと覚えてしまいます。
- 分からないまま本番環境（利用者が実際に使っている環境）で試す。まず練習用の環境で行い、迷ったら先輩に確認します。
