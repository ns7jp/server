# 記入して使う運用テンプレート

[入口](README.md)／[詳細設計](design.md)

必要な欄だけコピーする。普段は作業カード1枚で始める。既存のChange ID、Issue、試験ログがあれば参照し、同じ情報を再入力しない。下記の空欄は未記入であり、未実施の試験をPASSで埋めない。

```text

日付：
モード：個人ラボ／計画変更／障害対応
今日の目的（1つ）：
対象：リポジトリ・版・環境・サービス
未コミット差分／設定の識別：
今回の範囲：
今回の対象外：
見直し時刻／予算：

必須条件（期待結果と確認方法を先に記入）
安全・秘密・権限・データ保全：
必要な動作：
復旧・戻し方：
記録・説明・引継ぎ：

中断・復旧を判断する条件：
必要な連絡先／判断者（私的記録）：
次の1操作：

終了時
各条件の結果と証跡：
状態：作業中／保留／支援待ち／完了
追加案の保存先：
残っている影響と対象の現在状態：
次回の最初の1操作：
再開条件／次の見直し日：
```

## B. 60秒カード

```text
観測した事実：
元の目的：
新しい事実：あり／なし／未確認
今回解決する未達条件：
選ぶ行動：継続／追加案を保存／保留／支援待ち／終了候補を確認
根拠・証跡または再開条件：
```

短い記入例（架空）：

```text
事実：同じ成功runを2回開き直した。headと環境に変化なし。
行動：4枠の証跡を参照して終了。READMEの図の改善は金曜の採否待ちへ。
```

## C. 試験・証跡カード

```text
証跡ID：
作業ID／試験ID：
実施日時（タイムゾーン付き）：
実施者／自動実行の主体：
対象リポジトリ・コミット：
未コミット差分・設定の識別：
環境と対象サービス：
前提条件：
確認目的：
コマンド／手順（秘密値を含めない）：
期待値：
実測値：
結果：PASS／FAIL／NOT_RUN／NA
NAの場合の対象外理由と根拠：
証跡保存先：
保存期限／別保管先：
確認できた範囲：
確認できていない範囲：
再確認が必要になる条件：
```

証跡がなくなった場合は「証跡参照不可」。試験失敗と同一にせず、終了を判断する根拠が不足しているものとして扱う。昔の記録を使う場合は当時の日時を残す。現在確認していない事実の `verified_at` を進めない。

## D. 採否待ち箱

| ID | 追加案 | 元の目的との関係 | 今やらない理由 | 再開条件 | 見直し日 | 状態 |
|---|---|---|---|---|---|---|
| IDEA-記入 |  |  |  |  |  | 採否待ち |

記入例（架空）：

| ID | 追加案 | 元の目的との関係 | 今やらない理由 | 再開条件 | 見直し日 | 状態 |
|---|---|---|---|---|---|---|
| IDEA-DEMO | Grafanaで可視化する | 運用理解を深める次段階 | 初回は入口と認証の理解 | app／nginx実習を完了し、本人が次回対象に採用 | 次の週次レビュー日を記入 | 採否待ち |

AI提案も同じ箱へ置く。既に依頼された必要作業をこの箱へ移して放置しない。見直し日が来たら再評価し、採用は本人が決める。

## E. 保留と期限の記録

```text
作業ID：
保留日時：
保留理由：
未完の必須条件：
利用者／データ／稼働資源への影響：
保留時の対象状態：
担当：
次回の最初の1操作：
再開に必要な事実・環境・権限：
再開条件がなくても見直す日：
元の期限：
変更後の期限：
期限変更の理由：
元期限からの超過日数（該当時点）：
```

期限を変更するときは追記する。履歴を消す、元の期限を最新日へ置き換える、自動的に解決済みにする運用はしない。

## F. 5行の切り分け・支援カード

```text
1. 目的と影響：
2. 現在の状態と直前の変更：
3. 試したこと・期待値・結果・証拠：
4. 次の仮説と、それを否定できる観測：
5. 必要な支援・権限・判断／次の見直し時刻：
```

障害対応では別途、担当者・連絡経路・引継ぎ受領時刻を残す。自分が記録を書いた時点で、相手が引き受けたものとみなさない。個人ラボなら相談先が未定であることをそのまま記録する。

## G. 技術選定を閉じるカード

```text
判断ID／既存ADR：
満たしたい要件：
現行方式の具体的な不足：
比較した候補（まず現行＋1案）：
将来の効果／これからの負担／戻す方法：
小さな試験の合格条件：
撤退する条件：
今回の判断：採用／継続／保留／見送り
判断した人と日時：
根拠と未確認事項：
再検討する新事実・見直し時点：
```

「ここまで時間をかけた」は履歴に残してよいが、継続の根拠は今後の効果と必要負担で書く。

## H. Issue・PRに追加する最小欄

既存の変更要求とPRテンプレートに同じ項目があれば追加しない。

```markdown
### 今回の終了条件

- 目的：
- 必須条件と確認結果：
- 対象の版・環境・証跡：
- 未実施の確認と理由：
- 中断・戻す条件：
- 今回に含めない追加案の保存先：
- 保留時の再開条件：
```

チェック欄の印は実行証拠の代わりにならない。PR承認、CI成功、マージ、デプロイ、実環境での確認は別々に記録する。

## I. 日次の最小記録

```text
日付／作業ID：
今日できた事実と根拠：
未完または今回の対象外：
新事実なしの再確認／合格後の追加作業（概算分・不明なら欠測）：
この仕組みへの記入時間（概算分）：
次回の最初の1操作：
```

## J. 週次レビュー

```text
対象期間／見た作業ID：
必須確認を守れた終了件数／確認した終了件数：
未実施を成功扱いした箇所：なし／あり／未確認
新事実なしの再確認に使った概算時間：
合格後の範囲外作業に使った概算時間：
記入・通知・管理に使った概算時間：
手戻り・試験省略・引継ぎ不能：なし／あり／未確認
再開条件が成立した保留項目／再評価できた項目：
元期限を超えた項目と理由：
来週変える規則（1つ）：
本人の判断：継続／簡素化／停止
```

分母0は「対象なし」、データなしは「欠測」。他人との比較や人格評価には使わない。

## K. AIへ渡す作業指示のひな形

```text
目的は［今回の目的］です。
対象は［リポジトリ・版・環境・範囲］です。
完了条件は［必須条件と必要な証跡］です。
今回は［対象外］を追加しません。

必要な調査・修正・検証は、この依頼の範囲で完了まで進めてください。
新しい任意の改善案は採否待ち箱に記録し、自動採用しないでください。
新しい安全上の問題は影響と根拠を示して優先してください。
新事実なしに同じ調査を繰り返すときは、仮説を更新してください。
未実施・失敗・欠測・対象外を分け、実行していない結果を成功と書かないでください。
完了条件が満たされたら、結果・検証・限界を報告して終了してください。
```

この指示は作業範囲を明確にする補助である。入力に秘密情報を含めない。代理で本人の習得・経験・提案の採用を宣言させない。
