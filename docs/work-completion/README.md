# 手放して進める：サーバー構築の運用キット

**目的・合格条件・証拠・次回条件を先に決め、「まだ気になる」と思っていても、安全に作業を閉じられる仕組みです。**

ns7jp/serverの構築・試験・復旧・説明の流れに接続して設計しました。感情を自動で消すものではなく、観測した作業状況から次の行動を選ぶ補助です。

[リポジトリの入口](../../README.md)／[初心者ガイド](../beginner-learning-guide.md)／[既存の変更管理](../change-management.md)

## 使い始める

1. [詳細設計書](design.md)の「最初に採用する5つの規則」を読む。
2. [運用テンプレート](templates.md)の「今日の作業カード」を1枚コピーする。
3. 今日の目的を1つ選び、安全・動作・復旧・説明の合格条件を書く。
4. 通常作業は45分を最初の見直し目安にし、反復や追加案が出たら60秒カードへ進む。
5. 合格した範囲を閉じる。未完なら残課題と再開条件を残す。

45分・2回・週次10分は試行用の仮値です。障害中は既存の復旧・連絡体制を優先し、時間切れによる対応放棄をしません。

## 判定サンプル

Node.jsがある環境で実行します。詳細と架空の入力例は [automation/README.md](automation/README.md) を参照してください。ネットワーク通信、外部通知、GitHub書込み、サーバー操作、常駐処理は行いません。

CLIが示す終了候補は、入力に書かれた証跡情報の形式と対象版を確認した結果です。証跡の真実性や実環境の安全性は検証しません。人が内容を確認して作業を閉じます。

## 提供状態

- 詳細設計、テンプレート、ローカル判定サンプル：作成済み。
- ローカルの分岐テスト：結果は [根拠と検証](evidence.md) に記録。
- 文書の導線と判定コードのCI：このリポジトリに同梱。マージ・実行結果は対象PRとActionsで確認。
- 必須チェック設定、タイマー・外部通知・定期実行、実作業の情報収集：未実施。
- 実サーバー試験、本人の行動改善、運用負担の減少：未測定。

公開技術資料へ組み込む場合も、個人的な感情の記録は私的に保管します。元の依頼に必要な作業は完了まで進め、範囲外の任意改善だけを採否待ち箱へ移します。
