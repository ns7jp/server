## 発見事項

- `docker compose kill` / `docker kill` は、Docker 側に「意図的に止めた」と伝わり `restart: unless-stopped` を無効化する。「突然落ちた」を再現するには、コンテナのホスト側 PID に直接 `kill -9` する必要がある（[D-1-process-down.md](../D-1-process-down.md) に反映済み）
- nginx の upstream 名前解決は起動時の 1 回だけで、依存先（`app`）が落ちていると起動できない。`app` が落ちた状態で nginx 側だけ再起動されると、手動で `app` を起こすまで復旧しない
- WSL2 側が再起動すると、`mount --make-rshared /` の設定が消え、`node-exporter`（rslave マウントを使う）が起動できなくなる。恒久対応ではなく、都度の再設定が必要
- `restart: unless-stopped` は「デーモン起動時点で停止していたコンテナは自動起動しない」という仕様があり、WSL2 / Docker が裏で再起動すると、たまたま止まっていたコンテナだけ復旧されずに残る
