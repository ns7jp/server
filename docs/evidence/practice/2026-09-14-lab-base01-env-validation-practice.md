## 確認結果

EV番号は本結果票専用。PASSは画像から確認できた観点に限定する。

| ID | 観点 | 判定 | 結果・証拠 |
| --- | --- | --- | --- |
| EV-01 | 開始状態 | PASS | VMのユーザー・ホスト名、本文staging/8091、開始SHA-256を表示（E01） |
| EV-02 | 環境名拒否 | PASS（想定失敗） | stagng/8091を通常実行で指定。環境名候補のassertがfalse（E01） |
| EV-03 | 拒否時の停止 | PASS | ok0/changed0/failed1、終了2。後続の作成・生成タスクは表示されない（E01） |
| EV-04 | ファイル不変 | PASS | 拒否前後のSHA-256一致、本文staging/8091維持（E01） |
| EV-05 | 正常再実行 | PASS | All assertions passed、全3タスクok、changed0/failed0、終了0（E02） |
| EV-06 | 再実行後の状態 | PASS | SHA-256と本文が同じ。mainに演習ソース・生成物が未追跡で残る（E02） |

E01には--checkなしの実行コマンドとstagng指定が写っているため、今回の拒否は通常実行として記録する。
E02は入力行の上部が切れており、ポート8091は見えるがコマンド全体・環境名指定は未採録。
staging/8091へ戻す通常再実行を案内した後の結果として、role名・assert通過・集計・本文を確認した。
前段のcheck modeによるポート境界値試験とは区別する。

## ハッシュと最終状態

拒否前、拒否後、正常再実行後に表示されたapp.confのSHA-256は一致する。
値の原本は画像を参照し、機械可読なrawログ・対象ファイルは取得していない。
これは当該ファイルの内容比較であり、mtime・権限・全ディレクトリの不変性検査ではない。
添付のSHA256SUMS.txtは画像ファイル用であり、VM内app.confのハッシュではない。

最終本文はstaging/8091。mainに既存演習ファイルが未追跡で残り、追跡済みファイルの変更行は表示されていない。
今回、新しいPlaybook作成、入力検証処理の編集、Gitコミット、生成物削除は案内・記録していない。

## 未実施・限界

- 空環境名、大文字小文字、空白、ほかの不正環境名の比較は**NOT RUN**。
- 1件の入力ミス拒否を全入力パターンの保証にはしない。
- OS/Ansible版の再取得、全入力全文・ハッシュ、実行コミット、連続rawログは未採録。
- 実サービス起動・配備・ポート待受、複数ホスト実行は**NOT RUN**。
- server側の文書検査・CIは本人VM内の実行主体・対象とは別。
